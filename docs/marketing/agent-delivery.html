04 / 交付对账

大任务分给几个 Agent，
怎么收尾？

你能看到每件事谁在做、做到哪、文件在哪、谁检查。代码改完、文档没同步，任务不会显示完成；有人验收通过，才算交付。

任务领取/回滚已能用 产物协作部分能用 完整交付对账还在做

01 / 你会看到什么

每个任务有主，每个交付有状态。

你把一份报告拆给三个 Agent：一个查资料，一个写正文，一个做核验。打开任务页，你能看到谁领了什么、做到哪、卡在哪、交回了什么。

你会看到

任务卡：负责人、状态、依赖、截止时间、结果文件。谁在做、做到哪，一眼能看见。

你不会遇到

群聊里刷了半天，没人知道谁最后收尾；代码说完成、文档没更新，任务却显示全绿。

小任务不用分工。只有大文档、多角色、需要并行的任务，才值得拆给多个 Agent。

02 / 任务怎么分

领了才算开始，交回才算完成。

  1. 建任务写清目标、输入、验收标准、依赖关系。没写验收标准的任务，不算可执行任务。
  2. 领取一个任务同一时间只有一个有效负责人；重复派发不会重复执行。
  3. 尝试每次领取生成一个尝试编号；旧尝试的结果不能覆盖新尝试。
  4. 交回结果落到文件或记录里，任务状态变成「待验收」，不直接变「完成」。
  5. 回滚领取失败、成员失活、结果不合格，都能退回；不会留下假的「正在工作」。
你不需要盯聊天窗口。 任务页会告诉你：谁在做、做到哪、有没有卡住、结果在哪。
03 / 完成清单

「做完了」要拿得出四样东西。

一个大任务说完成，至少要有：

  • 代码/改动：改了什么、测试跑没跑、回归有没有过；
  • 文档：相关章节、CHANGELOG、接口说明有没有同步；
  • 引用：新增或修改的结论有没有来源；
  • 版本：文档版本和代码版本有没有对齐，差异有没有解释。

少一项，任务停在「待补齐」。只补几句总结不够，对应文件要真的更新。

这解决「一分工，收尾就散了」：每个 Agent 各自说完成不算数；同一张清单上，四样东西一起过。
04 / 文档怎么对上

代码往前走，文档也要跟着走。

代码 Agent 改完接口，文档 Agent 可能还不知道；写作 Agent 补了段落，核验 Agent 可能还在看旧版本。Codem 把版本对齐放进任务，不靠人临下班前想起来。

  • 代码改动关联到对应文档章节；
  • 文档改动关联到对应代码/任务；
  • 两边版本不一致时，任务保持「待补齐」；
  • 差异要写清楚，不能只写「已同步」。
你能看到的：任务卡上直接标「文档未同步」「接口说明缺失」「引用待补」。不用自己翻三个窗口对版本。
05 / 谁检查

写的人不验自己，验的人不参与写。

验收角色独立检查：代码能不能跑、文档有没有同步、引用是否支持结论、覆盖有没有缺口。发现缺口就退回，不能用「整体看起来不错」代替。

  1. 接收产物代码差异、文档版本、测试日志、引用清单。
  2. 按清单核验完成条件逐项过；未同步的文档、无来源的结论、没跑的测试都算缺口。
  3. 退回或通过缺口退回给对应 Agent；通过才更新任务完成状态。
  4. 留记录谁验的、验了哪些、依据什么，都能回看。
为什么独立：写代码的 Agent 容易只检查自己改的那一块；独立验收看的是整体交付，尤其是文档和版本有没有对齐。
06 / 边界

它做不到什么。

  • Agent 数量按任务需要。 小任务一个 Agent；大文档、多角色、并行任务才值得分工。
  • 群聊不适合当协调层。 群聊给人看；任务状态要落在任务页里。
  • 高影响动作仍需批准。 验收不能代替权限。
07 / 开发视角

给开发看的实现细节。

如果你不写代码，这一节可以跳过。

Task {
  id, title, status,          // pending / running / done / failed
  owner, attemptId,           // 谁领的、第几次尝试
  dependsOn: ["outline"],
  acceptance: ["代码可跑", "文档已同步", "引用已核验"],
  result: "artifact://..."
}

任务被领取时生成尝试编号；旧尝试结果不能覆盖新尝试；领取失败/成员失活时回滚状态。验收通过才更新完成状态，验收记录留审计。

位置负责什么状态
agent-teams/engine.ts任务、领取、尝试、回滚、邮箱已有实现
subagent/runtime.ts可续聊子会话、状态、恢复已有实现
goal/runner.ts阶段任务、验收证据、受控重规划已有实现
inbox等待/失败/需要人处理的通知已有实现

分工之后，要能交付。

任务状态、共享产物、文档对账、独立验收，四件事都做到，多 Agent 才不会越帮越乱。
