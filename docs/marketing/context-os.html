The old way

传统 Agent 的四个断点。

问题从来不是“模型不够聪明”。是上下文、文档、记忆和协作，各自停在了一次性窗口里。

01 / WINDOW

窗口一满，对话就断。

长任务做到一半，只能压缩、重开、再解释一遍。用户被迫管理上下文，而不是解决问题。

后果：长任务天然碎片化
02 / COMPRESSION

压缩之后，细节就没了。

摘要保住了“大意”，却丢掉了路径、数字、失败尝试和那句关键的原话。

后果：越压越像，越像越错
03 / MEMORY

记忆是黑盒，错了也不知道。

一条偏好从哪来、什么时候过期、和另一条是否冲突，用户看不见，模型也说不清。

后果：越用越不信任
04 / ARTIFACTS

文档、代码、任务，各活各的。

文档在附件里，代码在仓库里，任务在聊天里。Agent 每换一个窗口，就重新认识一次项目。

后果：协作靠转发，不靠事实
The Codem answer

不是更大的窗口，
是一套 Context OS。

把上下文拆成四个协作平面。模型只带当前需要的 1%，其余都在可检索、可验证的工作空间里。

01 / CONTEXT OS

一个 Thread，
多个 Segment。

对话是连续的，上下文是分段的。Codem 在后台判断“继续压缩”还是“换一段”，用户看到的始终是一个对话。

  • 不显示水位，不让用户做压缩决策
  • 旧消息原文保留，随时可按锚点回读
  • 每次只取当前任务的最小充分上下文

02 / DOCUMENT OS

文档不是附件，
是可编辑的工作区。

章节、表格、引用、版本、覆盖状态，都是可查询的结构。模型不必“记住全文”，但必须知道写到哪、依据是什么。

  • 大纲 / 段落 / 表格 / 引用，多粒度索引
  • Document Ledger 记录读过、改过、验证过
  • 分节写作 + 合并 + 一致性检查 + 引用验证

03 / MEMORY GRAPH

记忆不是提示词，
是可验证的数据库。

每条记忆都带来源、作用域、有效期和状态。冲突不覆盖，过期可识别，手动记忆永远优先。

  • 事实 / 偏好 / 决定 / 约束，分型存储
  • 来源、置信度、使用次数，全部可查
  • 不自动删除，不静默改写；合并要可撤销

04 / ARTIFACT-CENTRIC AGENTS

Agent 共享工件，
不共享一整段聊天。

Conductor 负责目标，Curator 负责上下文和记忆，Specialist 负责执行，Verifier 负责验收。它们通过任务图和工件协作。

  • 任务、依赖、领取、回滚，都有明确状态
  • 文档 / 代码 / 测试 / 决策，都是同一种 artifact
  • 群聊只是界面；协调靠账本，不靠刷屏

What changes

你不再需要，
替模型管理上下文。

四个平面带来的不是“更多按钮”，而是更少的上下文管理动作。

长任务，不再被窗口切成碎片。

上下文管理从“用户手动压缩”变成“系统按任务调度”。你继续说话，Codem 在后台决定带什么、换什么、留什么。

  • 不因接近上限而要求你开新会话
  • 旧消息不删除，可按段、按锚点回读
  • 每次请求只带当前任务需要的材料
  • 换段对用户透明，对模型有明确交接
// 用户看到的 thread: "一个连续对话" // 模型实际拿到的 workingSet = { task: "继续写第 4 节", recent: "最近 8 轮", sources: ["doc#42", "decision#7"], memory: ["偏好：中文"] } // 其余仍在 eventLog · documentGraph · memoryGraph

300 页文档，不是 300 次复制粘贴。

文档被解析成结构，任务被拆成章节。每一节都有来源、状态和验收，不需要把全文塞进一次请求。

  • 先大纲，再分节；每节独立阅读/写作
  • 合并时检查术语、数字、交叉引用
  • 引用可回到页码、章节、chunk
  • 覆盖账本明确“哪节还没读/没验”
// 不是一次 prompt plan = ["背景", "现状", "方案", "路径"] // 每节都有账本 section: { status: "verified", sources: ["p.12", "p.18"], claims: 3, citations: 3/3 } // 缺口不会被“摘要”吞掉 coverage: "18 / 29 sections"

记得对，比记得多更重要。

记忆是带来源、作用域和有效期的数据库。它不替你“猜”，而是让你能查、能改、能撤销。

  • 事实、偏好、决定、约束分开存储
  • 冲突保留双方，不静默覆盖
  • 手动记忆优先，自动提取只做候选
  • 跨项目隔离，不把 A 项目偏好带进 B 项目
// 一条可验证的记忆 fact: { statement: "发布前必须跑全量测试", scope: "project", provenance: ["msg#184"], confidence: 0.96, status: "approved", usage: 12 } // 冲突不覆盖 conflict: ["v1: 先跑定向", "v2: 先跑全量"]

多 Agent，不是多开几个窗口。

Agent 通过任务图和工件协作，而不是互相转发聊天记录。每个角色拿自己需要的那一小份上下文。

  • Conductor 负责目标、预算、停止和汇总
  • Specialist 只拿任务 + 相关切片 + 记忆
  • Verifier 独立检查引用、覆盖、一致性
  • 任务有领取、尝试、回滚，不重复执行

Trust by design

强大，不等于失控。

越是长任务、越多 Agent，越需要来源、审批、回滚和审计。Codem 把这些做成底座，而不是事后补丁。

来源可查

每个结论都能回到消息、页码、文件或提交；不是“模型记得”，是“这里有证据”。

变更可审

文档改动、记忆写入、Agent 任务都有 diff / 审批 / 审计记录，重要动作不静默发生。

失败可回

上下文段、任务、工件都可回滚；崩溃或重启后，按事件恢复，而不是从零再来。

本地优先

会话、文档、记忆默认留在本机；模型可选，数据边界由你决定。
