01 / 你会看到什么

你问一句，它能把上周的话找回来。

你换了一个新对话，问：「发布前还要跑什么？」Codem 找到上周那条记录：“发布前必须跑全量测试”，并带上来源。你点开，能看到当时的原话。

你会看到

你看到的是一条清楚的记录：它从哪来、在哪个项目生效、什么时候写的，都能查。

你可以做

确认、修改、删除，或者标成“只在当前项目用”。自动流程不能偷偷改你手动写的记忆。

如果这条记错了，你直接说「这条不对，改成发布前跑冒烟测试」。旧记录留下可追溯的替代关系，新记录从下一轮开始生效。

02 / 它记什么

一条记忆，至少要回答五个问题。

  • 说的是什么：一句能独立看懂的话，比如「发布前必须跑全量测试」。
  • 从哪来：哪条消息、哪份文档、哪次任务。
  • 在哪个范围生效：当前对话、这个项目、这个 Bot，还是只限本人。
  • 什么时候有效：从哪天开始，到哪天过期。
  • 现在是什么状态：候选、已确认、有争议、已归档。

这五项缺一项，记忆就容易变成“黑盒”：你看到一句结论，却不知道它从哪来、什么时候会过期、和另一条会不会冲突。

记忆和聊天记录分开存。 聊天记录保留原文；记忆是从原文里提炼出来、带出处的索引。你需要细节时，仍然能回到原话。
03 / 怎么取

只取这次相关的几条，不把全部记忆倒进来。

  1. 先看范围当前项目/对话能看哪些记忆；项目 A 的偏好不会带到项目 B。
  2. 再排相关按关键词、语义、来源可信度、时效和使用次数排；过期或低可信的降权。
  3. 需要时读全文先给索引；你追问细节时，再打开完整记录和来源。
  4. 回答带出处回答里标出来源；你能点回原对话、文档或任务。

这样既不把窗口塞满，也不会让你只看到一句没有出处的摘要。

04 / 冲突和过期

两条记忆打架，保留双方。

  • 冲突：一条说「发布前跑全量」，另一条说「只跑冒烟」。两条都留下，标出来源和时间，让你判断。
  • 过期：有有效期的记忆到期后降权或标为过期，不继续当现行事实。
  • 纠错：你说「记错了」，新记忆替代旧记忆，但旧记录留可追溯的替代关系。
  • 删除：由你显式删除或归档；自动流程不能偷偷删。
边界：记忆可能错，检索可能漏。别把记忆当权限、审批或法律事实；关键结论仍要回到原文和验收。
05 / 边界

它做不到什么。

  • 不能保证想起一切。 检索可能漏；所以关键结论要带来源，重要决定要写进文档或任务。
  • 不会把所有原文塞进每一轮。 原文留在历史里，记忆按需取；你仍然能翻、能搜。
  • 自动提取会出错。 所以它只产生候选；高影响写入要批准，手动记忆优先。
