03 / 记忆

记忆不是一句摘要，
是一条能查回原文的记录。

用户想翻所有对话和原文，不想只相信摘要。模型一次只能带一部分，所以 Codem 把“完整原文”和“当前要用的记忆”分开：原文留在时间线，记忆作为带出处的索引被检索。

01 / 原文与记忆

完整原文是底，记忆是索引。

“用户想看到所有记忆”并不意味着把所有原文塞进模型。它意味着：原文不能丢，用户能翻；模型需要时能按来源取回相关部分。

完整时间线

所有消息都在，包含被压缩的旧消息。可以搜索、回读、导出。这是“原文”的底。

记忆条目

从对话/文档/任务中提炼出的偏好、决定、事实、限制。每条带来源、范围、时间、状态。

摘要可以当入口，但不能当唯一真相。用户要核对时能回到原文；模型要细节时按锚点或检索读回那一段。

解决的是“只能看二手摘要”： 摘要告诉你“大概是什么”，原文和来源让你判断“到底是不是”。两者都要有。
02 / 数据结构

一条记忆，至少要有六个字段。

MemoryFact {
  statement: "发布前必须跑全量测试",
  scope: "project",              // 平台 / 项目 / 对话 / Bot / 群 / 团队
  provenance: ["msg_184"],       // 从哪来
  confidence: 0.96,
  status: "approved",            // candidate / approved / disputed / archived
  validFrom: "2026-11-01",        // 什么时候开始有效
  usageCount: 12,
  supersedes: ["mem_17"]           // 它替代了哪条旧记忆
}

这不是为了“看起来像数据库”，而是为了回答四个问题：

  • 这句话从哪来？
  • 在哪个项目/对话里生效？
  • 什么时候有效，什么时候过期？
  • 和另一条冲突时，谁替代谁？
03 / 写入

自动提取只产生候选，手动记忆优先。

  1. 提取候选从对话/文档里识别“可能是长期有用”的事实、偏好、决定；不是每句话都写。
  2. 去重与合并同主题候选先合并；相似度不够就不硬合；合并结果要能撤销。
  3. 按作用域审批项目级/高影响写入需要批准；对话级可按设置直接生效；平台级只手动。
  4. 落库并记来源写入 statement、scope、provenance、status；手动条目打上保护标记。
不会发生： 自动流程删掉或静默改写你手写的记忆；两条冲突记忆互相覆盖；把项目 A 的偏好带到项目 B。
04 / 读取

先过滤范围，再排序，再带引用。

  1. 范围过滤当前项目/对话/Bot 能看哪些记忆；跨项目默认不带。
  2. 相关性排序关键词/语义/实体匹配 + 来源可信度 + 时效 + 使用次数。
  3. 取全文不是只给 200 字摘要；需要时 memory_read 取完整条目和来源。
  4. 带引用回答回答里标出来源；用户能点回原对话/文档；冲突时把双方都摆出来。

记忆不是每轮全量注入。上下文里放索引/摘要，真正需要时再读全文；这样既能看到，又不把窗口塞满。

05 / 冲突与边界

冲突不覆盖，过期不装作还在。

  • 冲突：两条记忆说法不一致时，保留双方，标出来源和时间，让模型/用户裁决。
  • 过期：有 validTo 的记忆到期后降权或标为过期，不继续当现行事实。
  • 纠错：用户说“不是这样”时，新记忆可以替代旧记忆，但旧记录要留可追溯的 supersedes。
  • 删除：由用户显式删除或归档；自动流程不静默删。
边界：记忆可能错，检索可能漏。不要把记忆当权限、审批或法律事实；关键结论仍要回到原文和验收。
