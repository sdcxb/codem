01 / 对话主线

一条对话，
内部为什么要分成几段？

Codem 把「你看到的对话」和「模型这一轮看到的内容」分开存。旧消息留着，模型每轮只拿当前需要的一段。这样对话不用重开，模型也不会被整段历史压住。

01 / 数据结构

一条对话，两个对象：Session 和 ContextEpoch。

你看到的那一条聊天，在 Codem 里是一个 Session。模型这一轮实际拿到什么，由最新的 ContextEpoch 决定。

名字不用背，先记住一件事：工作段就是模型这一轮看到的那段上下文。 它在对话内部，不会新建对话。换段之后，对话记忆、侧边栏、远程查看都还在。

// 逻辑关系
Session（对话主线）
  ├─ ContextEpoch 1  kind="compact"   // 段内压缩
  ├─ ContextEpoch 2  kind="switch"    // 换工作段
  └─ ContextEpoch 3  kind="switch"
       cutoffMessageId = "msg_..."       // 从这条消息之后开始看

你看到的：时间线

所有消息都在，包括被压缩的旧消息。可以搜索、回读、导出。对应 listTimelineMessages。

模型看到的：本轮的版本

只取最新检查点之后的 marker + 尾部消息。对应 listMessages / ContextView。

cutoffMessageId 是按消息 id定位的，不按时间、不按摘要位置。模型从哪条消息开始看，可以精确复现；旧消息一条没删。

换段为什么不新建 Session？ 对话记忆、侧边栏、远程查看、分叉都挂在 Session 上。新建 Session 会把「换工作段」变成「换对话」。Codem 的做法是：Session 不变，只换模型看到的那一段。

02 / 压缩还是换段

快满时，有两种处理：压缩，或者换段。

压缩和换段用在不同的时点。压缩适合任务还没完、但过程可以收起来的时候；换段适合这一段确实可以收尾，或者压完还是太满。

动作什么时候用发生什么
压缩 compact任务没结束，过程多、结论少写检查点摘要，保留最近原文和关键用户消息；旧消息不删，模型从检查点之后继续。
换段 switch任务告一段落，或连续压缩后仍然太满写交接单，带最近原文和锚点；同一个 Session 里开新工作段；旧段仍可查。
  1. 先量占用系统提示、工具定义、输出预留都算进去，不只数聊天字数。
  2. 看任务有没有结束看用户要求、未回答的问题、还在跑的工具和验收条件，不要只听模型说「完成了」。
  3. 写交接单目标、限制、已完成、未完成、关键决定、关键文件、下一步、去哪里查。
  4. 保留最近原文交接单负责理解，最近原文负责语气、细节和刚说过的话；两者都要有。
  5. 换段，不换对话新段从交接单和尾部消息开始；旧消息仍在时间线；切换中的输入要转交，不丢。
当前状态：压缩路径已有检查点和完整时间线；自动换段还在分阶段开发，当前版本以压缩为主。
03 / 一次请求

把一次真实请求拆开看。

假设你说：「把登录流程改成支持扫码，保留原来的账号密码登录，补测试。」聊到第 80 轮，当前工作段快满了。

  1. 记下任务这句话进入对话主线；当前任务状态变成“改登录流程 + 补测试”。
  2. 写交接目标、已改文件、未完成的测试、关键决定（保留旧登录）、下一步。不要只写「登录改造中」。
  3. 留最近原文保留最近几轮的用户原话和关键工具结果，避免新段不知道刚才试过什么。
  4. 开新工作段新段从交接单、最近原文和锚点开始；旧段仍在时间线，需要时可回读。
  5. 继续输入你不需要点“新对话”；切换过程中输入会排队，提交到新段，不重复、不丢。
这一步解决「做一步就停了」： 模型快满时把任务状态交出去，换一个干净的工作段继续做。模型不用把整段历史都装进去，任务也不用重来。
04 / 旧内容

旧消息没有消失，只是不再全部塞给模型。

  • 完整时间线：按顺序看所有消息，包括被压缩的旧消息。
  • 全文检索：按关键词找旧对话；中文按字符/词组处理，不要求先分词。
  • 锚点：交接单记录“第几段、第几条”，需要时直接回到原文。
  • 工具结果：长输出落盘/落记录，模型按定位读取，不长期占上下文。

摘要只是入口，原文才是底。用户想核对时可以翻时间线；模型需要细节时按锚点或检索读那一段。

边界：检索靠关键词和锚点，不能保证「什么都能想起来」。交接单要写清楚去哪里查，不要只写结论。
05 / 边界

边界：它做不到什么。

  • 单次请求仍受窗口限制。 Codem 做的是把旧内容放到可检索的地方，让模型需要时能取。
  • 检索可能漏。 关键结论要带锚点，交接单要写清楚去哪里查。
  • 会有成本。 压缩、换段、检索都要花时间；省下的是重新解释和重做的成本。
