01 / 对话主线

一条对话，
内部为什么会有多个工作段？

答案不是“模型记性更好”，而是把“你看到的对话”和“模型这一次看到的内容”分开。旧消息不删，模型每次只取当前需要的那一段。

01 / 数据结构

对话主线是 Session，工作段是 ContextEpoch。

你看到的那一条聊天，在 Codem 里是一个 Session。模型实际拿到的上下文，由最新的 ContextEpoch 决定。

这两个名字不用背，只要理解一件事：工作段是对话内部的一段，不是新对话。 换段不会产生新的 Session，也不会把对话记忆、侧边栏、远程查看切断。

// 逻辑关系，不是表结构
Session（对话主线）
  ├─ ContextEpoch 1  kind="compact"   // 段内压缩
  ├─ ContextEpoch 2  kind="switch"    // 换工作段
  └─ ContextEpoch 3  kind="switch"
       cutoffMessageId = "msg_..."       // 从这条消息之后开始看

你看到的：时间线

所有消息都在，包括被压缩的旧消息。可以搜索、回读、导出。对应 listTimelineMessages。

模型看到的：投影

只取最新检查点之后的 marker + 尾部消息。对应 listMessages / ContextView。

cutoffMessageId 是按消息 id定位的，不按时间、不按摘要位置。模型从哪条消息开始看，可以精确复现；旧消息一条没删。

为什么不每次换段都新建 Session？ 因为对话记忆、侧边栏、远程查看、分叉都挂在 Session 上。新建 Session 会把“换工作段”变成“换对话”。Codem 的选择是：Session 不变，只换模型看到的那一段。

02 / 压缩还是换段

快满的时候，不是只有一个“压缩”。

压缩和换段解决的是不同问题。压缩适合“任务还没完，但有很多过程可以收起来”；换段适合“这一段确实可以收尾了，或者压完还是太满”。

动作什么时候用发生什么
压缩 compact任务没结束，过程多、结论少写检查点摘要，保留最近原文和关键用户消息；旧消息不删，模型从检查点之后继续。
换段 switch任务告一段落，或连续压缩后仍然太满写交接单，带最近原文和锚点；同一个 Session 里开新工作段；旧段仍可查。
  1. 先量占用系统提示、工具定义、输出预留都算进去，而不是只数聊天字数。
  2. 看任务有没有结束看用户要求、未回答的问题、还在跑的工具和验收条件，而不是只听模型说“完成了”。
  3. 写交接单目标、限制、已完成、未完成、关键决定、关键文件、下一步、去哪里查。
  4. 保留最近原文交接单负责理解，最近原文负责语气、细节和刚说过的话；两者都要有。
  5. 换段，不换对话新段从交接单和尾部消息开始；旧消息仍在时间线；切换中的输入要转交，不丢。
当前状态：压缩路径已有检查点和完整时间线；自动判断“压缩还是换段”还在分阶段落地。当前版本仍以压缩为主，不能把“自动换段”写成已经完成。
03 / 一次请求

把一次真实请求拆开看。

假设你说：「把登录流程改成支持扫码，保留原来的账号密码登录，补测试。」聊到第 80 轮，当前工作段快满了。

  1. 记下任务这句话进入对话主线；当前任务状态变成“改登录流程 + 补测试”。
  2. 写交接目标、已改文件、未完成的测试、关键决定（保留旧登录）、下一步。不是只写“登录改造中”。
  3. 留最近原文保留最近几轮的用户原话和关键工具结果，避免新段不知道刚才试过什么。
  4. 开新工作段新段从交接单、最近原文和锚点开始；旧段仍在时间线，需要时可回读。
  5. 继续输入你不需要点“新对话”；切换过程中输入会排队，提交到新段，不重复、不丢。
这一步解决的正是“做一步就停了”： 不是让模型无限装，而是让它在快满时把任务状态交出去，换一个干净的工作段继续做。
04 / 旧内容

旧消息没有消失，只是不再全部塞给模型。

  • 完整时间线：按顺序看所有消息，包括被压缩的旧消息。
  • 全文检索：按关键词找旧对话；中文按字符/词组处理，不要求先分词。
  • 锚点：交接单记录“第几段、第几条”，需要时直接回到原文。
  • 工具结果：长输出落盘/落记录，模型按定位读取，不长期占上下文。

“摘要”只是入口，不是唯一真相。用户想核对原文时可以翻时间线；模型需要细节时按锚点或检索读那一段。

边界：检索依赖关键词和锚点，不是语义上“什么都能想起来”。所以交接单要写清楚“去哪里查”，而不是只写结论。
05 / 边界

它不是什么。

  • 不是无限注意力。 单次请求仍受模型窗口限制；Codem 做的是把旧内容放到可检索的地方。
  • 不是自动记得一切。 检索可能漏，所以关键结论要带锚点，交接单要写“去哪里查”。
  • 不是零成本。 压缩、换段、检索都要花时间；省的是重新解释和重做的成本。
