01 / 你会看到什么

你看到的，还是一条对话。

普通做法里，窗口满了会提示你总结，或者新开一个对话。在 Codem 里，你继续输入；它不会多出一条「新会话」，也不会让你把背景重讲一遍。

你会看到

同一条聊天；第 1 天说过的话还在；输入框一直能用；回答接着上文，不会突然失忆。

Codem 在后台做

把已经处理完的内容收成一份交接；只把这次要用的材料带上；旧内容放回历史，不删除。

你可以像平时一样往上翻，也可以搜索旧消息。侧边栏、远程查看、分叉都还是这条对话，不会变成另一条。

这些都在后台完成。 你继续用同一条对话，往上翻、搜索、接着问，都不受影响。
02 / 快满时发生什么

窗口快满时，Codem 会先看任务做到哪。

它不会一看到占用高就打断你。先看你的要求有没有做完、还有没有没回答的问题、有没有正在跑的工具，再决定是收一收，还是从新的一段接着做。

  1. 先看任务有没有告一段落你的要求做完了吗？还有没有等你确认的事？工具还在跑吗？别只听它说「完成了」。
  2. 没结束，先把过程收起来写一份简短交接：做到哪、试过什么、卡在哪、下一步做什么。最近几轮对话保留原文。
  3. 结束了，就写交接单目标、已完成、未完成、关键文件、下一步、去哪里查。下一段从这张单子开始。
  4. 从新的一段继续你继续输入。界面上还是同一条对话，旧消息还在时间线里。
  5. 切换中的输入不丢你在这时发的消息会排队，提交到新的一段，不会重复，也不会掉。
当前版本：完整历史一直保留；自动整理已经能用一部分；什么时候该整理、什么时候该换一段，还在继续做。现在以整理为主。
03 / 一次真实对话

你让 Codem 改登录流程，聊到第 80 轮。

这时对话已经很长，快装不下了。你不需要做什么，继续问就行。

  1. 你继续问「扫码登录的测试补一下，账号密码登录别动。」
  2. Codem 收好上一段把已经改过的文件、没做完的测试、保留旧登录这个决定，写进交接；最近几轮原话留着。
  3. 你看到的没有变化还是同一条对话。它接着改代码，不会弹「请开新会话」，也不会让你再讲一遍为什么要保留旧登录。
  4. 你回头问旧决定过几轮你问「刚才为什么不用轮询？」Codem 会去翻旧消息或搜索，不会回你「我不记得」。
你要做的事只有一件：继续输入。 整理、交接、换段都在后台完成；旧内容一直能翻。
04 / 旧内容怎么找

旧消息没有被删，只是不再全部塞进这一轮。

  • 往上翻：所有消息按时间排着，包括很早以前的内容。
  • 搜索：输入关键词，找旧对话里的原话；中文按字符/词组处理。
  • 点引用：回答里的来源能回到原消息、文件或页码。
  • 看工具结果：长输出留在记录里，需要时再打开，不一直占着对话。

摘要只是帮你快速找到入口。要核对细节，回到原文；要接着做，Codem 只取这次相关的部分。

边界：搜索靠关键词和引用，不能保证「什么都能想起来」。所以交接单会写清楚去哪里查，别只写一句结论。
05 / 边界

它做不到什么。

  • 单次回复仍有窗口上限。 Codem 做的是把旧内容放到可搜索的地方，需要时再取。
  • 搜索可能漏。 所以关键结论要带来源，交接单要写清楚去哪里找。
  • 整理需要时间。 长对话切换时会有一次短暂停顿；换来的是不用重讲背景、不用重做。
06 / 开发视角

给开发看的实现名词。

如果你不写代码，这一节可以跳过。

在实现里，你看到的这条对话记作 Session；每次整理或换段记作 ContextEpoch。换段只改「下一次给模型看哪些消息」，不改对话本身，所以侧边栏、远程查看、分叉都还在。

// 逻辑关系
Session（对话主线）
  ├─ ContextEpoch 1  kind="compact"   // 段内整理
  ├─ ContextEpoch 2  kind="switch"    // 换到新一段
  └─ ContextEpoch 3  kind="switch"
       cutoffMessageId = "msg_..."       // 从这条消息之后开始看

cutoffMessageId 按消息 id 定位，不按时间猜。模型从哪条消息开始看可以精确复现；完整时间线不变，旧消息一条没删。
