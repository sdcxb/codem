02 / 长文档

300 页文档，
怎么写到最后一章还不散？

Codem 不把全文塞进模型，也不把文档切成互不相干的 chunk。它先把文档拆成结构，再用一本账记录读过什么、改过什么、验过什么。

01 / 文档结构

文档先有章节和页码，才谈得上理解。

一份 300 页报告，如果只有一整段文本，模型只能看到开头或结尾。Codem 先把目录、章节、段落、表格、页码变成可查询的坐标。

模型可以先用 doc_outline 看目录，找到相关段落后用 doc_search 定位，再用 doc_read 只读需要的那几段。每次读取都带页码、章节、chunk 引用，不会给一段没有出处的文本。

// 文档拆成可定位的片段
Document {
  id, name, version,
  outline: ["01 背景", "02 现状", "03 方案"],
  chunks: [{ page, heading, text }],
  status: "ready"
}

结构树

目录和章节让模型知道「现在写的是哪一块」，不用只从相似段落里猜上下文。

页码/引用

每个结论能回到页码、章节、chunk；用户和核验角色都能查。

已有实现：doc_outline / doc_search / doc_read / citation
02 / 文档账本

不靠模型“记得”，靠一本账。

长文写到后面，跨轮需要保留的只有三类信息：看过哪些文件、读过哪些片段、确认了哪些带引用的事实。正文随时可以按引用再取。

DocumentLedger {
  files: ["报告.docx", "访谈记录.pdf"],
  reads: [{ documentId, chunkNo, page, heading, at }],
  facts: [{ text, citation, at }],
  coverage: { "04 实施路径": "drafting" }
}

账本放在每轮会变的尾部，不放进稳定的系统前缀。否则每改一节，整个提示词前缀都变，缓存失效。账本只记结构化状态，不复制整段正文。

账本要回答四件事：第 4 节写过没有、第 2 节的结论是什么、哪句有引用、哪里还没核验。模型不用记住全文，但这些状态不能丢。

03 / 完成条件

代码改完，文档没更新，不算完成。

大型任务最常见的失配：代码已经往前走，架构文档、CHANGELOG、接口说明还停在上一版。下一个接手的人看到的是旧结论。

Codem 把文档更新写进任务完成条件，不靠人临下班前想起来：

  • 代码任务：代码、测试、相关文档、CHANGELOG 是否有状态；
  • 文档任务：章节是否已写、是否已核验、引用是否完整；
  • 版本对账：文档版本和代码版本是否对齐，差异是否解释；
  • 没同步：任务保持「待补齐」，不能标完成。
对应「多 Agent 收尾就散了」的问题：每个 Agent 各自说「我完成了」不算数；同一张交付清单上，代码、文档、测试、引用一起验收。
04 / 长任务流水线

大纲 → 分节 → 合并 → 核验 → 对账。

  1. 拆结构目录、章节、段落、表格、页码；确认文档状态和 OCR/解析质量。
  2. 列大纲先确定每一节写什么、依据哪些来源、完成标准是什么。
  3. 逐节写每次只取当前节相关材料和账本；写完更新该节状态和引用。
  4. 合并检查术语、数字、交叉引用和前后结论；冲突时保留双方，不偷偷覆盖。
  5. 核验每条结论有来源；未读章节、未验段落、无引用结论，账本里都要能看到。
  6. 对账文档版本、代码版本、任务状态对齐后才交付。

这套阶段可以交给 goal runner 或等价阶段机执行：每阶段有验收证据，没做完就不标完成。

05 / 一次真实请求

把“改第 4 节”拆开看。

你说：「把年度报告第 4 节改一下，补上回滚方案，别动前面的结论。」

  1. 取材料第 4 节原文 + 第 1～3 节已确认结论 + 账本 + 两条相关记忆；不会把整本报告塞进来。
  2. 读和改先 doc_read 第 4 节范围，再生成修改；改动带 diff，不直接覆盖旧版本。
  3. 写回账本第 4 节状态改为“已改/待核验”；记录依据的来源和引用。
  4. 核验检查回滚方案是否漏、是否和前面结论冲突、引用是否支持。
  5. 对账文档版本 + 代码/任务状态一致后才回复完成。
模型不用记住整本报告。 它只需要知道第 4 节在哪、前面确认了什么、这次改了什么、依据是什么。
06 / 边界与代码

边界与代码位置。

  • 向量检索只能解决一部分。 它能找到相似段落，但接不上章节关系、术语和前后结论。
  • 不同格式难度不同。 PDF、扫描件、表格、PPT 的解析质量不一样；OCR/表格失败要显式标出来。
  • 不能自动写完整本书。 分节、合并、引用核验仍需要任务状态和人工/独立验收。
