# 01 · 产品总览：Codem 是什么、能做什么、边界在哪

> 基线：**1.16.331**（2026-10-23 发布）｜ 2026-10-26 重编
> 本文回答“产品层”的问题；实现细节见 `02`–`08`，当前状态见 `09`。

---

## 1. 一句话

**Codem 是一个 Windows 优先的桌面 AI 编程助手**：把「对话 → 计划 → 工具调用（读写文件 / 跑命令 / 终端 / 浏览器）→ 验证」整条 Agent 循环做成图形界面，对标 Codex / Claude Code / DeepSeek Harness（DSH）。

- 产品名：**Codem**（包名 `com.codem.app`）
- 仓库：`github.com/sdcxb/codem`，主分支 `master`
- 技术形态：**Tauri v2（Rust）+ React 18 + TypeScript**，WebView2 渲染，SQLite（WAL）本地存储
- 分发：NSIS `.exe` + WiX `.msi`，GitHub Releases + minisign 自动更新
- 作者自述：十年没敲代码、全程用 Codem / MiMoCode 自己开发自己 ⇒ 仓库里大量中文注释在解释“为什么”，改动前先读注释

## 2. 目标用户与典型场景

**目标用户**

- 单人开发者、小团队中的“全栈/独立开发者”；
- 希望把代码、密钥、会话留在本机，不接受把仓库整体交给云端 Agent；
- 需要长任务、跨天任务、多任务并行，但不想自己当“人肉调度器”。

**典型场景**

| 场景 | Codem 的做法 |
|---|---|
| 让 AI 改一个真实仓库的 bug | 对话 → 计划 → `read/grep/glob` 侦查 → `edit/write` → `bash` 跑测试 → 收尾门禁 |
| 长会话上下文不够 | 水位监测 → 工具输出/参数折叠 → 70% 自动压缩（最近 3 轮不切断）→ 90% 才提示 |
| 同时推进 3–8 个任务 | 项目工作台：协调者会话 + 并行 thread + 独立 git worktree + `project_report` 证据 |
| 把重复工作自动化 | 任务中心：定时/文件监听触发器、Issues、看板、收件箱、团队模板 |
| 在手机/微信上继续 | Phone Link（LAN 扫码配对）或微信 ClawBot 桥，把消息接回本机会话 |
| 让 AI 用外部能力 | MCP 服务器、技能（SKILL.md）、插件（Cordis/YAML 装配）、CodeGraph、语义检索 |
| 做演示/文档 | 内置 PPT 生成与编辑器、知识笔记本（NotebookLM 风格）、富内容渲染 |
| 摸鱼 | 桌面宠物（独立窗口、精灵动画、市场）、三套皮肤、内置大富翁 |

**非目标（至少当前版本）**

- 云端沙箱 / 云端长跑 / 多用户团队权限；
- PR 自动创建、CI 自动修复、review 评论自动处理（PR/CI 只读）；
- 把所有会话强制纳入“项目协调者”；
- 用提示词替代结构（本项目的明确工程取向）。

## 3. 差异化（相对通用 CLI Agent）

1. **本地优先**：会话、附件、索引、密钥都在本机；数据库是自研 Rust SQLite 引擎（WAL、单写者、类型化仓储、不接受裸 SQL）。
2. **图形化 Agent 循环**：计划步骤、工具卡、Diff、审批、上下文水位、轨迹、任务中心都是可见的；不是“黑盒流式文本”。
3. **项目工作台**：协调者 + thread + worktree + 可重验 gate，混合模式（普通会话仍可用）。
4. **插件/技能/MCP 三层扩展**：Cordis 依赖注入 + YAML 装配清单 + UI 槽位；技能是文件系统里的 `SKILL.md`。
5. **长会话工程**：按距离分档压缩、工具结果/参数折叠、前缀缓存稳定性、原始 token 水位。
6. **可核查的工程纪律**：判据 + 变异 + 真机取证 + 结构审计 + 评测对照；发布说明面向用户、不写内部编号。
7. **桌面集成**：托盘、宠物窗、Mica/Acrylic 材质、终端 PTY、浏览器窗口、系统通知。

## 7. 对标结论（截至 2026-10，来自仓库内评测记录）

- **12 个真实仓库修复任务**：Codem 通过 **10**，DSH 通过 **9**（同一套任务、同一模型、同一推理强度）。
- **效率**：完成同样任务所需工具调用约为 DSH 的 **一半**；输出 token 明显更少。
- **仍弱的一项：单次响应时延（约慢 1.5 倍）**。已定性：310 次调用中 **99% 时间在等模型服务端**，客户端处理仅 **1.1%**，服务端速率批内极差仅 7% ⇒ 差异来自**账号/路由**，产品内改不动。
- **已接受的采样方差**：`repo-06` / `repo-09` 同一构建在不同轮次可能通过或不通过；曾尝试“零改动收尾闸”被两条既有判据证否并撤销。

> 这些是仓库内的评测口径，不是第三方认证。发布说明里不会出现“测试轮数/通过率/采样波动”等内部数字（用户要求）。

## 8. 产品原则（会影响你怎么改代码）

1. **结构优于提示词**：能靠代码/契约/门禁解决的，不加“再提醒模型一句”。
2. **诚实失败**：不把失败伪装成“已完成 / 已保存 / 已是最新”；用户无法介入的自检只进日志。
3. **证据可追踪**：完成必须有判据/真机证据；项目工作台用 `project_report` + gate 重验，不接受口头完成。
4. **本地优先**：默认不把代码/密钥送云；只有用户显式开启的搜索/插件/远程能力才出网。
5. **一次交付**：禁止目标模式/自动续跑（用户明确要求）；多步用清单，岔路直接问。
6. **改动可回退**：版本、迁移、快照、worktree、撤销入口都尽量保留。

## 9. 术语表（读代码前先统一）

| 术语 | 含义 |
|---|---|
| **Session / 会话** | 一条对话线程；有 `sessions` 行 + JSONL 日志 + 消息索引 |
| **Project / 项目** | 一个仓库目录；普通模式只是文件夹，项目工作台模式额外有 `.codem/project/` 状态 |
| **Thread** | 项目工作台里的并行会话；可绑定独立 git worktree |
| **Coordinator / 协调者** | 项目里的“负责人”会话；只读项目状态，拆任务/收报告/收口 |
| **Turn / 回合** | 一次用户输入到 Agent 停止（可能含多次 LLM 迭代） |
| **Iteration / 迭代** | 回合内的一次 LLM 请求 + 工具批次 |
| **Tool / 工具** | LLM 可调用的函数；有 `ToolDef`、契约、输出 schema、渲染器 |
| **Skill / 技能** | 文件系统里的 `SKILL.md` + 资源；按需加载，不是代码插件 |
| **Plugin / 插件** | Cordis 服务提供者；由 YAML 装配，可启停；UI 插件通过 Slot 提供组件 |
| **Slot / 槽位** | UI 扩展点；single/list/keyed/chain 四种 |
| **MCP** | Model Context Protocol 服务器；工具/资源由外部进程提供 |
| **Compaction / 压缩** | 把旧消息换成摘要标记，保留最近轮次；分三档 |
| **Fold / 折叠** | 只读地把旧工具输出/参数换成短存根，不改历史原文 |
| **Water level / 水位** | 当前上下文占用比例；70% 自动压缩，90% 提示 |
| **Memory / 记忆** | 平台/项目/会话三层持久事实；自动提取 + 审批 |
| **Gate** | 项目验收命令；`project_report` 里的 passed gate 会被重跑 |
| **OFM** | Our Free Model，内置免费模型插件（独立 Node 进程） |
| **DSH** | DeepSeek Harness，主要对标对象 |
