## §0 一句话结论

**能力上我们已经不弱于 Pi，而且在"用户可感知的稳健性"上领先**（权限体系、审批闸门、崩溃自愈、

## §3 Codem **落后**的地方（附证据与代价）

### 3.1 【结构性·最大】没有"执行环境抽象层"⇒ **跑不了远端/容器**

- **事实**：Pi 1.0.4 新增 `packages/env/`（`@earendil-works/pi-env`）：把文件/命令/监视操作
  搬到**另一台机器**执行（SSH + 自带 Rust daemon，定长帧协议），本地用 `RemoteExecutionEnv`
  实现同一个 `ExecutionEnv` 接口。证据：`packages/env/src/ssh.ts`（保守 ssh 选项 +
  `--` 防参数注入）、`:370-375`（远端落点按 sha256 命名）、`docs/protocol.md:12-35`（帧格式）、
  `daemon/src/main.rs:1-41`（5s ping / 30s 静默自杀 / 杀自己起的进程组）。
- **Codem 侧**：`src/core/file-api.ts` 是**函数式直调**（每个函数自己 `invoke` Tauri 命令），
  **没有** `ExecutionEnv` / `FileSystem` / `Shell` 这类可替换的抽象层。
- **代价**：**大**。Pi 侧 5 个 TS 源文件（`remote-env.ts` 34KB）+ Rust daemon 13 个文件
  （`sys/windows.rs` 25KB）+ 4 份文档；**前置依赖是先把文件层重构成抽象层**（伤筋动骨）。
- **⚠️ 关键事实**：`@earendil-works/pi-env` 在**Pi 自己的仓库里没有任何消费者** ——
  **上游自己都还没把它接进产品**。
- **建议**：**观察**。等上游接进 CLI 并证明有用再评估；现在做等于替上游趟一条他没走的路。

### 3.2 【结构性】超大数据的第一公民支持：有界读 + 文件监视

- **事实（读）**：Pi 的 `read` 只读"文件头 + 一次行扫描 + 要展示的那几行"
  （`BinaryReader.scanLines()`，`env/line-scan.ts` 145 行），上限 `2000 行 / 50KiB`；
  并用**成对差分测试**（`tools-read-differential.test.ts`，1600 组）保证与"整文件算法"逐字段相等。
- **Codem 侧（真机已量到的一半）**：`read_file_lines` 是**单次扫描**同时给出
  `totalLines` / `droppedLines` / `droppedChars`（第 181 波 T-3，**真机读数逐条相符**），
  但它是**逐行读完整文件**才给出 `totalLines` ⇒ **GB 级文件仍会慢**（不是"读不回来"，是"要等"）。
- **事实（监视）**：Pi 的 `FileSystem.watch` 有**明确的不确定态 `overflow`**（"这段时间覆盖不可信，
  请全量重扫"）、Identity 绑 **inode** 而不是路径、Windows **默认轮询**（因为原生 watcher 会让
  父目录无法重命名）。Codem 用 git 状态比对（`file-change-tracker.ts`）——覆盖了"本轮改了什么"，
  但**没有"外部改动的实时感知"**。
- **代价**：读侧**中**（需要可寻址的二进制读取接口 + 一次流式扫描）；监视侧**中**
  （`node-watch.ts` 439 行 + 一致性测试），但 Windows 上代价是**2 秒延迟 + 周期性全量
  `readdir+lstat`**（上限 10000 目录）。
- **⚠️ 关键事实**：上游 `durable/docs/spec.md:2860` 明写 **"Durable itself never calls it"**。
- **建议**：**读侧做**（`read` 只读"够用的那部分" —— 判据强、纯收益、无平台风险）；
  **监视侧不做**（"实时感知外部改动"不是我们用户的需求，而开销是持续的）。

### 3.3 【精细经营】缓存与上下文：两处我们完全没有的机制

- **① 会话身份持久化（prompt-cache 亲和）**：Pi 把 `sessionId` 作为**对话级文档**持久化
  （`harness/provider.ts` 39 行：`fork: "initial"` 让每个 fork 拿新身份、旧对话惰性回填、
  正常路径零写），发给模型做 prompt-cache 亲和。证据：`generation.ts:205` +
  真实 e2e（8 回合内 `cacheRead===0` 只在首回合、之后 3 回合命中率 ≥0.9）。
  **Codem 侧**：靠**稳定前缀**（date 尾置、>95% 公共前缀断言）拿缓存命中 —— 第 45 轮实测
  **99.947%** 命中率，**已达到同等量级**。所以这一条**我们不缺**（机制不同、结果齐平）。
- **② 可回退的上下文编辑（`context_edit`）**：Pi 允许**只改模型上下文**的追加式记录 ——
  把一次失败尝试从模型上下文里摘掉，而**原始历史 / 导出 / 账单都不动**，且编辑**分支相对、可回退**
  （`docs/session-format.md:139-147`、`agent-session.ts:2994-2998` 用它做溢出修复）。
  这是"**重试一次而不必对用户撒谎说没发生过**"的机制。
  **Codem 侧**：没有等价物 —— 我们的压缩（compaction）会**真实改写历史**，模型侧与存储侧无法分叉。
- **代价**：会话身份**小**（我们已经齐平，不需要做）；`context_edit` **中**（要在事件日志/投影里
  引入"仅模型可见的编辑层"，且必须保证导出/账单/回放三条路径都不受影响）。
- **建议**：会话身份**不做**（已齐平）；`context_edit` **值得评估** ——
  它直接对应我们的一个真实痛点：**失败重试会污染上下文**。

### 3.4 【产品级】MCP 的 OAuth 2.1 与 resources

- **事实**：Pi 的 MCP 客户端自带 OAuth 子集（发现 / PKCE / 动态注册 / CIMD / 刷新 /
  401 自动重认证 / `insufficient_scope` 权限升级），并把 `resources/list|templates|read`
  暴露成三个模型可调用的工具（`readOnlyHint`，命名对齐 Codex/opencode）。
  1.0.4 的增量是 `application_type`（OIDC 服务器默认把客户端当 `web`，从而**拒绝 http 环回
  重定向 URI** ⇒ 登录直接 `invalid_redirect_uri` 失败）。
- **Codem 侧**：`MCPClient` 支持 stdio + HTTP/SSE，**没有 OAuth**，**没有 resources 工具**。
- **代价**：**大**（OAuth 单独 ~50KB 源码 + 22KB 测试；resources 339 行 + UI 渲染）。
- **建议**：**观察 + 先问自己一个问题**：用户实际要连的 MCP 服务器里，**有没有需要 OAuth 登录的**？
  如果只有 stdio 本地服务（如 codegraph/zvec），这个成本换不来可感知收益。
  反过来，**resources 的性价比明显高于 OAuth**（339 行换"能读服务器暴露的只读数据"）。

### 3.5 【小】若干"做过就能少踩坑"的细节

| 项 | Pi 的做法 | 我们的现状 | 建议 |
|---|---|---|---|
| **截断诊断的形状** | 结构化 diagnostics：`Output truncated to its end: N lines, M bytes dropped`，**渲染进 content 尾部**，且用 `final.content === content` 兜住"钩子改写后不许再声称截断" | 第 181 波已给精确 lines/chars（真机量到），但**没有渲染成结构化诊断**（只是提示行） | **做**（沿用同一形态，判据断言完整拼接串） |
| **`image()` 产物落盘** | `wx` 独占创建 + `0600` + 内容去重 + 写失败写进标签 + **先截断后落盘** | 无 `image()` 通道 | **做**（作为"若加图片输出"的规格先记下） |
| **BOM 在分块边的处理** | `ignoreBOM: true` + 只在整条流起点丢一个前导 BOM，并有**双向测试** | 走 `BufReader::lines()`，不经流式 BOM 解码 | **不做**（架构不同，风险不存在） |
| **按思考档位的采样参数** | `samplingParamsByThinkingLevel`（三级合并 model → 档位 → 请求） | 只有 `reasoningEffort` 贯通 | **观察**（无真实需求证据；且显式 `undefined` 会覆盖默认值这个坑值得记住） |
| **工具暴露词表**（`direct/model-only/codemode/deferred/hidden`） | 五值词表 + `store()/load()` + 207 行脚本 API | 只有"注册/未注册" | **不做词表**；但**"隐藏 ≠ 移除"的教训要记住**：一旦我们有了"按开关裁剪工具"的能力，**同一可见性规则必须在列表/规则/提示词三处同源**（Pi 那边正是在这里出过漏洞） |

## §4 诚实记录：本轮**没做成**的一件事（T-1）

`ToolExecuteResult.isError` 必填化：`tsc` 报 **187 处 / 33 文件**，本轮把**可静态判定的 81 处
（43%）**填好了，剩余 **106 处是真正的歧义**：

| 类别 | 数量级 | 为什么不能机械做 |
|---|---|---|
| 纯拼接模板串（`` `${stdout}\n\n${stderr}` ``） | 最多 | 成败由上游决定，**不在这一行** |
| 静态文字里成败都像/都不像 | 若干 | 需要读业务语义 |
| `output` 是变量/调用（`result.message`、`lines.join("\n")`） | 若干 | 同上 |
| `output` 不是字段列表里的一项（6 处） | 6 | 结构不同，插入点不成立 |
| 联合返回的 34 处签名不匹配 | 34 | 要逐分支判断 |

**撤回原因**：逐条人工判定的上下文代价远大于收益，且会让本轮无法收尾 ⇒ 按纪律撤回类型改动，
**保住已完成的 MCP 修复与已提交的 T-2/T-3/T-4**；工具链（`.preview-shot/_t1-fill.mjs`，
AST + 按文件批量 + 每文件重解析校验 + 位置去重）与逐条清单留档供下一轮直接收口。

> **为什么这条对"与 Pi 的差距"有影响**：Pi 的工具失败是**显式声明**的（`isError` 一类契约），
> 而我们的失败在**内容型工具**（`read`/`grep`/`web_fetch`）上仍靠"不推断"兜着 ——
> 那是个**已知的静默缺口**（判据 `TRS-2` 把形状钉住了）。**它的修法就是 T-1。**

## §6 一句话收尾

**"我们和 Pi 的差距"已经不是"能力差距"，而是"取舍差异"** ——
Pi 把复杂度投在**执行环境与持久化的研究栈**上（且**自己都还没接进产品**），
我们把复杂度投在**权限、审批、崩溃自愈与判据密度**上（真机上都能量到）。
所以接下来该做的不是"补齐 Pi 有的"，而是：
**① 把已确认的静默缺口收口（T-1）；② 把大数据路径做扎实（有界读 + 结构化截断诊断）；
③ 只在"用户能感知"的地方引入新机制（resources、context_edit），并明确拒绝剩下的。**
