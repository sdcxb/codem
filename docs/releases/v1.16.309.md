# Codem v1.16.309

**发布日期**：2026-10-10
**类型**：稳定版（Windows x64）
**下载**：`Codem_1.16.309_x64-setup.exe`（NSIS 安装包）· `Codem_1.16.309_x64_en-US.msi`（MSI）

## 本版要点

1. **装好即用的免费模型** —— 本版内置了开源项目 **Our Free Model**（MIT）的本地服务：一个只监听本机
   回环地址的小程序，**不需要登录、注册或填 API Key**，模型清单跟随上游刷新。安装后**默认开启**，
   对话的模型列表会**优先**显示它当前可用的免费模型（取不到时自动回退到你自己配的模型，列表不会空）。
2. **它完全独立，随时可以关掉** —— 「插件管理 → 插件市场」里有一张卡片：开启 / 暂停 / 删除。
   暂停只是停掉它（数据保留），删除会连它的数据一起清掉；两种操作都会把它登记的那条供应商一并撤销，
   你原有的模型、密钥、对话**一点都不受影响**（已实测：暂停状态下照常发消息、正常得到回答）。
3. **起不来会直说** —— 它需要机器上有 Node.js 22 或更高：没有 Node 会明确告诉你；起来了但服务没就绪，
   卡片上会直接显示**它自己的运行日志**，而不是只说一句"失败了"。上次异常退出（崩溃/断电）留下的
   运行锁，本版也会自己识别并清理，不用你手工处理。

## 变更

### 新增

- 内置免费模型插件（Our Free Model 的本地服务）：OpenAI 兼容的本地网关，提供 `/v1/models` 与
  `/v1/chat/completions`（含流式）。
- 模型列表优先级：开启时它的清单排在最前；未启用 / 未就绪 / 缓存过期时**原样回退**。
- 「插件管理 → 插件市场」新增控制卡片：一句话状态（端口、模型数、进程号、Node 来源）、
  开启 / 暂停 / 删除 / 刷新，以及未就绪时的运行日志。
- 把它登记为一个可调用的供应商（`free-model`），密钥**只在本机内存里注册、不落盘**；
  暂停或删除时立刻撤销。

### 修复

- 上次异常退出后插件拒绝再启动的问题：现在启动前会确认"运行锁的主人确实不在跑了"再清理。
- 暂停后模型列表还会在最长一分钟内挂着调不通的模型：现在暂停/删除会**立刻**把它从列表撤下来。

### 说明

- 该插件是**第三方开源项目**（MIT），本版内置的是它自带的独立本地服务；随安装包提供，
  构建时按固定版本拉取并逐文件校验。它发出的请求直达上游公开网关（不是 Codem 的服务器）。
  上游的免费池会在其模型卡中声明"提示词可能被记录用于改进服务"——**请不要用它发送敏感内容**。
- 插件的账号渠道（十三个第三方账号通道）本版没有启用，免费模型不需要任何账号。

## 对标结果

**本版未重跑对标评测**，沿用上一稳定版的结论：在 **12 个真实仓库修复任务**上，本版通过 **10 个**，
参考实现（DSH，同一套任务、同一模型）通过 **9 个**；完成同样任务所需的工具调用约为参考实现的一半，
输出 token 用量明显更少；单次响应时延仍慢于参考实现（取决于模型服务端，客户端侧不是瓶颈）。

本版改动全部落在"记忆写入判定""内置插件与模型列表"上，没有触碰 agent 循环与工具链路，
因此沿用上面的数字。

## 升级说明

- 覆盖安装即可；已有的会话、记忆、待批准条目、供应商与设置原样保留。
- 首次启动会尝试把插件带起来（**默认开启**）。如果机器上没有 Node.js 22+，它不会影响 Codem 的任何功能，
  卡片上会说明原因；装好 Node 后点一下「刷新状态」或重启即可。
- 若不想要它：点「暂停」（保留数据）或「删除」（清掉数据），之后不会再自动启动。

## 已知问题

- 输入框里的模型下拉在本版是**展示用**（模型清单会列出，但切换用得在"档案/设置"里选）——
  "点一下就把当前对话切到某个免费模型"会在后续版本里补。
- 插件把免费模型分了两组（可用 / 地区受限），个别模型可能被上游拒绝（例如返回
  `Model does not support this protocol.`）——那是上游对该模型的限制，插件仍会把它列出来。
- 免费池由上游免费提供，可用性与速度随上游波动；它不是 Codem 的服务，也不能保证长期可用。

## 校验

- 附更新器签名 `.sig`；`latest.json` 平台键为 `windows-x86_64-nsis` 与 `windows-x86_64`（同一份签名）。
- 安装包 sha256 与更新器清单一致（可用仓库内 `tools/release/verify-update-manifest.mjs --remote` 复核）。
