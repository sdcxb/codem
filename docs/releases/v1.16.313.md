# Codem v1.16.313

**发布日期**：2026-10-12
**类型**：稳定版（Windows x64）
**下载**：`Codem_1.16.313_x64-setup.exe`（NSIS 安装包）· `Codem_1.16.313_x64_en-US.msi`（MSI）

## 本版要点

1. **免费模型：新增「检测可用性」—— 刷得出来不等于能用**
   - 你问得对：「刷新模型列表」原来只把上游目录拉回来，而那份目录里**没有**"这个模型现在通不通"的信息，
     所以你会在列表里看到一调就报「上游不可用」的模型。
   - **现在**：插件卡片上多了「检测可用性」按钮 —— 它给每个模型发**一条最小请求**
     （只生成 1 个 token，不是跑一次真实任务；每个请求都有超时、并发有上限），
     然后如实告诉你结论，例如**「检测完成：18/25 个可用，7 个当前不可用」**。
   - **结论会标在模型列表上**（设置里的模型列表和对话里的模型选择器都会有）：
     不可用的显示「（当前不可用 · N 分钟前检测）」。**同时记时间** —— 结论超过新鲜期、
     或者上游恢复了，标注就自动消失（不会"明明好了却一直劝退你"）。
   - **不用你手动点也会越来越准**：真实对话撞到"上游该模型不可用"时，顺手把那个模型记下来。
   - **「慢」和「不可用」分开**：个别模型只是慢（实测有模型 1 个 token 的探测通过、真聊天 60 秒没答完），
     这种标「（最近一次调用超时 · N 分钟前）」而**不**说成不可用 —— 免得你永久避开一个其实能用的模型。
   - 不做成自动的：几十个模型逐个探测要十几到几十秒，塞进「刷新」会让每次刷新都卡住。
     也**不会自动替你换模型**（自动换模型会让你觉得"我选的模型自己变了"）。
2. **修掉每次启动闪一下黑窗口**：内置 Node 之后，应用启动时会去查"有没有残留的插件进程"等，
   而这些是**控制台程序** —— Windows 上直接起它们会先建一个控制台窗口，于是黑框一闪。
   现在这些调用都加了"不创建控制台窗口"，并加了一条**源码级门禁**：以后任何新增的进程调用漏了它，
   测试会当场失败。
3. **内置 Node 不再从安装目录运行**（上一版已开始，本版延续）：插件运行的是**数据目录里的副本**，
   安装目录只剩只读资源 ⇒ 升级不会再被"文件正被占用"挡住。

## 变更

### 新增
- 免费模型「检测可用性」（逐个最小请求探测 + 结果带时间戳）+ 模型列表上的可用性标注。
- 应用真实调用失败/超时时自动回写可用性结论（越用越准）。

### 修复
- 每次启动闪一下黑窗口（进程调用未加"不创建控制台窗口"）。
- 可用性结论的"假成功"：检测结果落盘失败时，界面会如实说"结论未能保存，重启后需重新检测"。

## 对标结果

**本版未重跑对标评测**，沿用上一稳定版的结论：在 **12 个真实仓库修复任务**上，本版通过 **10 个**，
参考实现（DSH，同一套任务、同一模型）通过 **9 个**；完成同样任务所需的工具调用约为参考实现的一半，
输出 token 用量明显更少；单次响应时延仍慢于参考实现（取决于模型服务端，客户端侧不是瓶颈）。

本版改动集中在内置免费模型插件的可用性探测与进程启动细节，没有触碰 agent 循环与工具链路。

## 升级说明

- 覆盖安装即可；已有的会话、记忆、待批准条目、供应商与设置原样保留。
- **如果你是从 1.16.310 / 1.16.311 升级**：那两版的插件会运行**安装目录里**的 Node，
  安装程序覆盖它时可能弹出「无法打开要写入的文件：…\resources\node\node.exe」。
  遇到时请**先完全退出 Codem 再装**，或直接点 **[Ignore]**（两版内置的是同一个 Node v24.19.0，
  跳过它没有副作用；**别点 [Retry]**）。装到本版之后，这个文件不再被插件占用，以后升级不会再被挡。
- 想省事可以直接在插件卡片上点一次「检测可用性」，之后模型列表就会带可用性标注。

## 已知问题

- 「检测可用性」探测的是**此刻能不能回话**，不保证生成速度与质量；个别模型会"探测通过、真聊天很慢"
  （这类会显示「最近一次调用超时」，与你手动探测的结果分开记录）。
- 免费池是**第三方公开网关**（不是 Codem 的服务器），其模型卡里声明"提示词可能被记录用于改进服务"
  —— **请不要用它发送敏感内容**；上游模型会随时上下线，换一个 `-free` 模型即可。
- 探测每个模型都要真发一次请求，因此**几十个模型会花十几到几十秒**，期间按钮显示「检测中…」。

## 校验

- 附更新器签名 `.sig`；`latest.json` 平台键为 `windows-x86_64-nsis` 与 `windows-x86_64`（同一份签名）。
- 安装包 sha256 与更新器清单一致（可用仓库内 `tools/release/verify-update-manifest.mjs --remote` 复核）。
