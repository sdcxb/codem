# Codem v1.16.317

**发布日期**：2026-10-13
**类型**：稳定版（Windows x64）
**下载**：`Codem_1.16.317_x64-setup.exe`（NSIS 安装包）· `Codem_1.16.317_x64_en-US.msi`（MSI）

## 本版要点

1. **记忆审批可以双击展开全文 —— 不用再盲批**
   - 你报的：审批的时候看不到详细信息，无法评估审批是否通过。待批准的记忆原来每一行只显示
     **前 80 个字**；自动提取的长条目里，这 80 字常常只是铺垫 ——「这条到底在说什么」
     「批准之后会在哪生效」都读不出来，只能盲批或盲拒。
   - **现在**：**双击任意一条**待批准记忆，就地展开它的完整信息：
     - **完整内容**（一个字都不截断）；
     - **作用域与生效范围**（平台级 / 项目级 / 对话级，以及批准后到底管哪些对话）；
     - **归属**（哪个项目、哪个对话；就是当前这个的话会写明；没有归属键的会如实说
       「批准也不会进上下文」）；
     - **来源**（手动维护还是自动提取）、**状态**、**批次**（可整批撤销）、
       **最后修改时间**、**标签**。
     再双击一次收起。
   - 列表摘要照旧只有 80 字（全文都铺在列表里，待批准区会变成一整面墙，"逐条处置"就没法用了）；
     **双击落在勾选框 / 批准 / 拒绝上不会触发展开**，那些按钮的行为一个字没变。
   - 待批准区上方有一句常驻提示写明这个手势。

## 变更

### 新增与改进
- 待批准记忆**双击展开**完整内容与判断依据（作用域 / 生效范围 / 归属 / 来源 / 状态 / 批次 / 时间 / 标签）。

### 修复
- 记忆审批区只给 80 字摘要、看不到全文与归属，"该不该批准"无从判断的问题。

## 对标结果

本版未重跑对标评测，沿用上一稳定版的结论：在 **12 个真实仓库修复任务**上，本版通过 **10 个**，
参考实现（DSH，同一套任务、同一模型）通过 **9 个**；完成同样任务所需的工具调用约为参考实现的一半，
输出 token 用量明显更少；单次响应时延仍慢于参考实现（取决于模型服务端，客户端侧不是瓶颈）。

本版改动集中在记忆审批界面，没有触碰 agent 循环与工具链路。

## 升级说明

- 覆盖安装即可；已有的会话、记忆、待批准条目、供应商与设置原样保留。
- 如果你还停在 1.16.310 / 1.16.311：升级时可能弹出「无法打开要写入的文件：…\resources\node\node.exe」，
  遇到时请**先完全退出 Codem 再装**，或点 **[Ignore]**（别点 [Retry]）；装到 1.16.313 之后不会再被挡。

## 已知问题

- **免费模型池是第三方公开网关**（不是 Codem 的服务器）：上游按自己的政策随时上下线模型 ——
  例如它自家的免费车道现在只允许它自己的客户端使用，这类模型会被标记为不可用并从列表里隐藏。
  可用性结论**带时间戳、30 分钟后自动失效**（上游恢复后模型会自己回到列表），
  也可以点插件卡片上的「检测可用性」重新检测。
- **部分免费模型的模态信息上游没有提供**，界面上显示【未知】—— 我们不用名字猜；
  要变确定需要实测（发一张极小图片看接口是否接受图像输入）。
- 免费池的模型卡里声明"提示词可能被记录并用于改进服务"——**请不要用它发送敏感内容**。
- 退出时的「卡一下 / 要按两次」：此前已把退出路径上的同步等待改成"发出去不等"（有判据与变异守着），
  但**尚未在真机上完成端到端计时确认** —— 如仍遇到请反馈现象。

## 校验
