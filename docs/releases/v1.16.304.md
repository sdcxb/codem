# Codem v1.16.304

**发布日期**：2026-10-09
**类型**：稳定版（Windows x64）
**下载**：`Codem_1.16.304_x64-setup.exe`（NSIS 安装包）· `Codem_1.16.304_x64_en-US.msi`（MSI）

## 本版要点

> 上一稳定版是 `1.16.299`，本版一次性包含其后所有改动。

1. **记忆的作用域真正按归属生效**：项目级记忆只在这个项目里出现、对话级只在这个对话里出现、平台级对所有项目生效。设置里新增「**记忆体检**」，按三级作用域（另加「归属未知（旧数据）」）分组列出每条记忆，能一眼看清它属于哪里、来自哪里、会不会进上下文。
2. **自动提取的记忆现在真的存得下**（这一条是本版最有价值的修复）。此前模型返回的正文里只要带**没转义的引号**（例如用直引号去引用一个中文词）或**真实换行**，整批提取结果会被判为解析失败而**一条都不保存** —— 用户看到的现象就是「自动记忆不好使」。现在这两类都能正确解析；顺带把失败时的日志改成能定位的（打印出错位置附近的原文）。
3. **每条消息的查询索引以前一直写不进去**：写入消息时会弹「数据保存失败…本次改动只存在于内存，重启后会丢」，控制台同时刷同类错误。消息正文没有丢（它写在会话日志里，索引可由日志重建），但搜索与会话计数一直不准确。现已修好，并补了判据把这类写法钉住。
4. **「有一批记忆等着批准」离开面板也看得见**：侧栏「记忆」入口上有角标显示待批准条数（与记忆面板顶部那个数字同源），清零后自动消失，点它直接打开记忆面板。默认审批开启时自动提取的记忆先进待批准区、不参与上下文，以前只有打开面板才知道有多少条在等。
5. **旧数据迁移可回退**：升级时迁移过来的旧记忆会保留**迁移前快照**，可在体检里一键回退；旧版跨项目共享的记忆单独归入「旧版跨项目记忆（可能被污染）」一组并提供**暂停注入**开关，先核对再决定怎么用。
6. **记忆注入划出了显式的缓存边界**：记忆按**易变性**分成稳定侧（平台级手动条目）与易变侧（项目级/对话级/自动提取/旧数据），两块之间有无条件出现的边界标记。这样只改易变侧时前缀缓存仍能命中（实测前缀保留约 98%），不会因为记忆篇幅变化打坏整段缓存。
7. **存量用户的记忆读不出来**：新版一度只认一种容器形状，而真实存量数据是「以条目 id 为键的映射」⇒ 升级后拒绝加载、记忆读不出来。现在接受该形状并正常迁移，**条目一条不丢**。
8. **时间显示错 8 小时、条目日期差一天**：时间上下文此前用 UTC 拼本地偏移，整体错 8 小时；条目日期用 UTC 日，本地 00:00–08:00 之间会显示成前一天。现在全仓统一到一处时间口径。
9. **`.cmd` / `.bat` 启动参数的报错更可操作**：带双引号 / 百分号 / 感叹号 / 换行的启动参数仍然会被拒绝（逐条实测确认：这些字符在「外层 cmd → 目标脚本」两跳之间无法保证逐字节不变，且部分写法会让参数尾部被当成命令执行），但报错现在给出替代办法：想让 `%APPDATA%` 展开就直接填展开后的绝对路径、含空格或中文的参数不必自己加引号、多行内容先写进文件再传路径。
10. **记忆快照回退后的两处不一致**：回退后侧栏角标会停在旧数字（现在立即刷新）；回退提示原来指向「作用域无法识别」组，而旧条目实际落在「归属未知（旧数据）」组（现在两个组名都在提示里，且与体检里真实存在的组名同源）。

## 对标结果

已重跑对标评测（12 个真实仓库修复任务，同一模型、同一推理强度）：

- **本版通过 10 个**（两轮都通过；单轮分别为 11 个与 10 个），**参考实现（DSH）通过 9 个**（两轮都通过；单轮均 10 个）。
- **效率优于参考实现**：完成同类任务所需的**工具调用约为参考实现的一半**（每对中位 45.6 / 53.3 次 vs 94.0 / 90.8 次）。
- **输出 token 两轮互有高低**（约为参考实现的 0.67× 与 1.12×），本版不再稳定占优 —— 如实列出。
- **仍弱于参考实现的一项**：单次响应时延。实测差异来自模型服务端与账号路由（客户端处理只占约 1%），产品内改不动，本版未针对它做改动。

## 变更

### 新增与改进

- **记忆三级作用域**按归属键严格生效；新增「记忆体检」视图（分组列出 + 逐条归位 + 批量处置 + 导出快照 + 回退）。
- **记忆来源三态**（手动 / 自动 / 未知（旧数据））在注入、界面、体检、导出、保护口径上完全一致；自动提取默认**需要批准**；容量达上限时如实告知失败，不再静默驱逐旧条目。
- **批次撤销与导出/导入往返保真**：一次批量导入或自动提取可整批撤销；导出的记忆再导入回来内容一致。
- **记忆注入按易变性两分**并给出**显式缓存边界标记**；块内条目按持久化创建序渲染，编辑一条不再造成块内顺序平移；`[[链接]]` 受同侧约束。
- **侧栏「记忆」入口新增「待批准」角标**（与面板数字同源、清零即消失、点击进面板）。
- 中文标点与全角字符的显示口径统一（「」等）。

### 修复

- **自动记忆提取**：正文里未转义的引号、未转义的真实换行都会让整批结果被判为解析失败而全部丢弃；现在两类都能解析，失败时日志打印出错位置附近的原文（可定位）。
- **消息索引**：每条消息的查询索引写入都失败（调用时丢了对象自身）⇒ 搜索与会话计数不准，并弹出用户可见的「数据保存失败」横幅。消息正文未受影响。
- **记忆读取**：只认一种容器形状导致存量用户的「以条目 id 为键的映射」被拒 ⇒ 记忆读不出来；现在接受并正常迁移。
- **时间口径**：时间上下文整体错 8 小时；条目日期用 UTC 日导致本地凌晨显示成前一天。
- **记忆快照回退**：回退后外壳角标停在旧数字（现在回退成功即刷新）；回退提示指向了错的组（现在点名体检里真实存在的两个组）。
- **旧版数据**：迁移前快照与回退；旧版跨项目池单列并支持暂停注入；存量条目的归属不明时不会被静默塞进平台级。

## 升级说明

- 可直接覆盖安装，无需手动操作；设置与历史会话沿用原有数据。
- 首次启动会对旧版记忆做一次迁移（**迁移前自动留存快照，可回退**）。
- 更新器清单同时提供 `windows-x86_64-nsis` 与 `windows-x86_64` 两个平台键。

## 已知问题 / 后续

- 个别评测任务存在模型侧采样方差：同一构建在不同轮次可能通过或不通过，与构建本身无关。
- 旧的跨项目记忆在迁移后仍会在所有项目生效，直到你删除、归位或「保留为平台级」；体检里提供了批量处置与暂停注入。
- 单次响应时延主要取决于模型服务端，客户端处理占比很小；本版未针对时延做改动。
