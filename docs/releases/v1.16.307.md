# Codem v1.16.307

**发布日期**：2026-10-10
**类型**：稳定版（Windows x64）
**下载**：`Codem_1.16.307_x64-setup.exe`（NSIS 安装包）· `Codem_1.16.307_x64_en-US.msi`（MSI）

## 本版要点

1. **待批准的自动记忆现在显示作用域**（平台级 / 项目级 / 对话级）—— 以前只有标题和正文，
   看不出这条记忆批准之后会影响多大范围，只能猜。现在每条都带一个三色徽标，鼠标悬停会说明
   「批准之后会怎样」：平台级＝所有项目所有对话、项目级＝这个项目以后的每个对话、对话级＝只影响当前对话。
2. **系统提醒不再假装是你发的消息** —— 引擎为了把活干完会往对话里插几句 [SYSTEM] 提醒
   （例如「改了文件但没验证」），重新打开对话时它们以前会显示成**你自己发的消息**（你的头像、你的格式，
   还带「编辑并重发」）。现在统一按「系统说明」渲染：居中、没有你的头衔、没有编辑入口，正文照旧看得见。

## 变更

### 新增与改进

- 待批准区每条记忆带**作用域徽标**：平台级 / 项目级 / 对话级（三色区分 + 悬停说明生效范围）。
- 认不出来的旧作用域**原样显示**（例如「作用域：workspace」），不会被猜成这三种之一。
- **没有归属键**的待批准条目额外标出「无归属」—— 这种条目批准了也不会进上下文，免得白批一次。
- 作用域文案收敛为唯一一份（记忆面板与「记忆体检」共用），避免同一件事出现两种说法。

### 修复

- 引擎插入的系统提醒（改了文件没验证、收尾前待说明事项、输出截断续跑、上下文压缩摘要等）
  不再被渲染成用户自己的消息；同一条规则也用于**轮次边界**（提醒不再把一个回合切成两段）、
  **对话总览**（不再多出假提问轮次）与**滚动条标记**（不再多出一串假的「你」标记）。
- 加固：新增一道自动检查，将来再往对话里插入新的系统提醒时，如果它没有被识别出来，构建期检查会失败。

## 对标结果

**本版未重跑对标评测**，沿用上一稳定版的结论：在 **12 个真实仓库修复任务**上，本版通过 **10 个**，
参考实现（DSH，同一套任务、同一模型）通过 **9 个**；完成同样任务所需的工具调用约为参考实现的一半，
输出 token 用量明显更少；单次响应时延仍慢于参考实现（取决于模型服务端，客户端侧不是瓶颈）。

本版改动全部落在**记忆与消息显示**上，没有触碰 agent 循环、工具链路与提示词主链路，因此沿用上面的数字。

## 升级说明

- 覆盖安装即可，无需手动操作；已有的会话、记忆、待批准条目与各项设置原样保留。
- 已发布的旧版本无法从 1.16.307 回退（安装包可覆盖降级，但记忆与设置不会回滚）。

## 已知问题 / 后续

- 待批准条目如果归属的项目 / 对话已经不存在（例如工作目录被删除），记忆面板里看不到它们，
  需要在「记忆体检」里查看与处置；那类条目现在会明确标出「无归属」/「作用域无法识别」。
- 一条自动记忆被「拒绝」等于删除它，目前没有「拒绝记录」：同一件事在**另一个对话**里仍可能被重新提出。
- 上下文压缩摘要会以「系统说明」的形式出现在对话里（它本来就不是你发的话）。

## 校验

- 附更新器签名 `.sig`；`latest.json` 平台键为 `windows-x86_64-nsis` 与 `windows-x86_64`（两者同一份签名）。
- 安装包 sha256 与更新器清单一致（可用仓库内的 `tools/release/verify-update-manifest.mjs --remote` 复核）。
