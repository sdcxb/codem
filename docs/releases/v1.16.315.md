# Codem v1.16.315

**发布日期**：2026-10-12
**类型**：稳定版（Windows x64）
**下载**：`Codem_1.16.315_x64-setup.exe`（NSIS 安装包）· `Codem_1.16.315_x64_en-US.msi`（MSI）

## 本版要点

1. **免费模型：刷新之后会自动测一遍，"不能用的"不会再出现在列表里**
   - 上一版虽然会把已知不可用的模型隐藏，但**可用性结论需要你先点一次「检测可用性」**；
     结论超过 30 分钟就当作"未知" ⇒ 于是**刷新之后列表里还是会出现一调就报错的模型**（你遇到的就是这个）。
   - **现在**：点【刷新模型列表】**之后会在后台自动检测一次**（不阻塞，刷新按钮点完立刻可用），
     检测完成后列表自动更新，把不可用的模型隐掉；**启动时如果结论已过期也会在后台自动补测**。
   - **刷新提示与列表数量一致**：以前只报「✓ 获取到 25 个模型」，你会以为这 25 个都能用；
     现在如实报 **「✓ 获取到 25 个模型 · 已隐藏 7 个当前不可用的（可见 18 个）」**，
     与列表里真实可见的数量完全一致。
2. **「关于」里的旧名称已修正**：以前显示 `Codem (mimo-gui) v…`，现在是 `Codem v…`；
   内置示例插件（大富翁）地图的署名也一并改掉。

## 变更

### 修复
- 刷新模型列表后，不可用的免费模型仍然出现在列表里（现在刷新后自动补测，并在测完后隐藏）。
- 刷新提示只报"拉回来多少"，与列表里可见数量不一致（现在提示与列表共用同一口径）。
- 「关于」里显示旧名称 `mimo-gui`。

## 对标结果

**本版未重跑对标评测**，沿用上一稳定版的结论：在 **12 个真实仓库修复任务**上，本版通过 **10 个**，
参考实现（DSH，同一套任务、同一模型）通过 **9 个**；完成同样任务所需的工具调用约为参考实现的一半，
输出 token 用量明显更少；单次响应时延仍慢于参考实现（取决于模型服务端，客户端侧不是瓶颈）。

本版改动集中在内置免费模型插件的列表呈现与"关于"文案，没有触碰 agent 循环与工具链路。

## 升级说明

- 覆盖安装即可；已有的会话、记忆、待批准条目、供应商与设置原样保留。
- 如果你还停在 1.16.310 / 1.16.311：升级时可能弹出「无法打开要写入的文件：…\resources\node\node.exe」，
  遇到时请**先完全退出 Codem 再装**，或直接点 **[Ignore]**（别点 [Retry]）；装到 1.16.313 之后不会再被挡。
- 想看当前哪些免费模型可用：插件卡片 →「检测可用性」；或者直接点一次【刷新模型列表】（现在会自动测）。

## 已知问题

- **「不可用」是带时间戳的结论**：超过 30 分钟自动失效（上游可能已恢复）；隐藏的模型会在结论过期后
  自动回到列表，或在下次自动/手动检测后回来。
- 「检测可用性」与后台自动检测探测的是**此刻能不能回话**，不保证生成速度与质量；
  探测通过但真聊天很慢的会显示「最近一次调用超时」。
- 免费池是**第三方公开网关**（不是 Codem 的服务器），其模型卡里声明"提示词可能被记录用于改进服务"
  —— **请不要用它发送敏感内容**；上游模型随时上下线，属预期。
- 退出时的「卡一下/要按两次」：本版之前已把退出路径上的同步等待改成"发出去不等"（有判据与变异守着），
  但**尚未在真机上完成端到端计时确认** —— 如仍遇到请反馈现象。

## 校验

- 附更新器签名 `.sig`；`latest.json` 平台键为 `windows-x86_64-nsis` 与 `windows-x86_64`（同一份签名）。
- 安装包 sha256 与更新器清单一致（可用仓库内 `tools/release/verify-update-manifest.mjs --remote` 复核）。
