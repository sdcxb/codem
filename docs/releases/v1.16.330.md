# Codem v1.16.330

## 发布信息

- **发布日期**：2026-10-23
- **类型**：稳定版（Windows x64）
- **下载**：`Codem_1.16.330_x64-setup.exe`（推荐）· `Codem_1.16.330_x64_en-US.msi`

## 本版要点

**插件管理现在能真正管理版本了。** 「插件管理 → 已安装」新增了外部 DSH 插件卡片：读取本机 DSH profile 里 npm 安装的插件版本，和 registry 最新版比较；有更新时点「升级并安装」，装完会回读 `package.json` 确认版本确实变了。`npm view` 或安装失败会如实报错，不会把「没查成」显示成「已是最新」。

这条链路用真实插件 `dsh-ops` 跑过：从 0.4.0 检测到 0.4.1，通过界面升级并回读成功。之后停用它，Codem 的会话、bash 工具、插件管理仍然正常——外部插件的代码本来就不注入 Codem 运行时，停用只影响版本/管理状态。

**所有插件有了统一的详情页。** 点击任意插件卡，会打开同一个详情弹层：版本、描述、类型、依赖/被依赖、提供的服务、风险、启停与重启。以前「免费模型插件」在列表里铺开一整套控制面板，占掉大半个屏幕；现在它和其他插件一样只占一个网格卡位，完整的开启/暂停/删除/模型列表面板收进它自己的详情页。卡片上的开关也不会再误弹详情。

## 修复

- **删除运行中的会话会立即结束它的命令进程树**：不再把 `ping` 之类的后台命令留成孤儿；会话删除后到达的迟到事件也不会再写入已删除的会话，避免存储报错。
- 插件开关点击不再冒泡触发详情弹层。

## 对标结果

本版没有改动 agent 循环、模型路由或上下文策略；12 个真实仓库修复任务的对标批未重跑，能力结论沿用上一版，不把未复测的数字当成新结论。

## 已知问题

- 外部 DSH 插件的检查/升级依赖 npm registry 网络；离线或 registry 不可达时，卡片会显示检查失败，不会伪装成「已是最新」。
- 外部插件升级只更新本机 DSH profile 的 npm 包；不会自动重启 DSH，也不会把插件注入 Codem。
- 插件详情页展示的是插件自身声明的元数据；没有写描述的旧插件会显示「暂无描述」。
