# Codem v1.16.314

**发布日期**：2026-10-12
**类型**：稳定版（Windows x64）
**下载**：`Codem_1.16.314_x64-setup.exe`（NSIS 安装包）· `Codem_1.16.314_x64_en-US.msi`（MSI）

## 本版要点

1. **免费模型：不可用的模型不再出现在列表里**（上一版只做了标注，这版做到底）
   - 你指出的问题是对的：上一版把不可用的模型**标注**出来了，但**仍然列在列表里** ⇒ 你还是会选中它、再报一次错。
   - **现在**：设置里的模型列表与对话里的模型选择器都会把「已知不可用」的免费模型**过滤掉**；
     并如实告诉你「（已隐藏 N 个当前不可用的免费模型 —— 点插件卡片上的「检测可用性」可刷新结论）」。
   - **当前正在用的那个会留着**（带「当前不可用」后缀）—— 否则你不知道自己在用什么。
   - **结论会过期**：超过 30 分钟新鲜期就自动解除隐藏（上游可能已恢复）；想立刻更新就再点一次「检测可用性」。
2. **免费模型的可用性结论现在会区分「不可用」与「慢/超时」**
   - 个别模型只是慢（实测有模型 1 个 token 的探测通过、真聊天 60 秒没答完），这种显示
     「（最近一次调用超时 · N 分钟前）」而不是「不可用」—— 免得你永久避开一个其实能用的模型。
3. **修掉每次启动闪一下黑窗口**（内置 Node 之后启动时会查残留插件进程，那些是控制台程序）。
   现在这些调用都加了"不创建控制台窗口"，并有**源码级门禁**保证以后新增的调用不会漏。

## 变更

### 修复
- 免费模型列表里仍然列出不可用的模型（现在隐藏 + 如实说明隐藏数量）。
- 可用性结论把「慢/超时」与「不可用」混为一谈。
- 每次启动闪一下黑窗口。

## 对标结果

**本版未重跑对标评测**，沿用上一稳定版的结论：在 **12 个真实仓库修复任务**上，本版通过 **10 个**，
参考实现（DSH，同一套任务、同一模型）通过 **9 个**；完成同样任务所需的工具调用约为参考实现的一半，
输出 token 用量明显更少；单次响应时延仍慢于参考实现（取决于模型服务端，客户端侧不是瓶颈）。

本版改动只涉及内置免费模型插件的列表呈现与进程启动细节，没有触碰 agent 循环与工具链路。

## 升级说明

- 覆盖安装即可；已有的会话、记忆、待批准条目、供应商与设置原样保留。
- 如果你还停在 1.16.310 / 1.16.311：升级时可能弹出「无法打开要写入的文件：…\resources\node\node.exe」，
  遇到时请**先完全退出 Codem 再装**，或直接点 **[Ignore]**（两版内置同一个 Node，跳过它无副作用；
  **别点 [Retry]**）。
- 想看当前哪些免费模型可用：插件卡片 →「检测可用性」（约 20–30 秒）。

## 已知问题

- 「检测可用性」探测的是**此刻能不能回话**，不保证生成速度与质量；探测通过但真聊天很慢的，
  会显示「最近一次调用超时」。
- 免费池是**第三方公开网关**（不是 Codem 的服务器），其模型卡里声明"提示词可能被记录用于改进服务"
  —— **请不要用它发送敏感内容**；上游模型随时上下线，属预期。
- 退出时的「卡一下/要按两次」：本版把退出路径上的同步等待改成了"发出去不等"（有判据与变异守着），
  但**我们尚未在真机上完成端到端计时确认** —— 如果你仍遇到，请把现象反馈给我们。

## 校验

- 附更新器签名 `.sig`；`latest.json` 平台键为 `windows-x86_64-nsis` 与 `windows-x86_64`（同一份签名）。
- 安装包 sha256 与更新器清单一致（可用仓库内 `tools/release/verify-update-manifest.mjs --remote` 复核）。
