# Codem v1.16.308

**发布日期**：2026-10-10
**类型**：稳定版（Windows x64）
**下载**：`Codem_1.16.308_x64-setup.exe`（NSIS 安装包）· `Codem_1.16.308_x64_en-US.msi`（MSI）

## 本版要点

1. **你拒绝过的记忆不会再回来问你第二次** —— 以前「拒绝」等于直接删掉、什么都不留，于是下一轮、
   下一个对话（或换了工作目录之后）模型把同一件事重新推导出来，**你又被问一次**。
   现在拒绝会留一条记录，之后自动提取遇到同类事实（换个说法也算）就**不再写入、也不再请你批准**。
2. **你在对话里明确要求记住的内容照常放行，而且直接生效** —— 你说了「记住这个」，它就不会再让你点一次批准。
3. **记忆体检里能看到「已拒绝 N 条」，也能一键清空** —— 误点一次拒绝不至于永久锁死（清空后这类事实
   可以重新被自动提取）。

## 变更

### 新增与改进

- 拒绝（含批量拒绝、以及删除一条**待批准**的提议）会留下一条「已拒绝」记录：标题、正文摘要、
  当时的作用域、拒绝时间。记录**有界**（只保留最近 60 条），存进记忆库本身，重启后仍然生效。
- 自动提取在写入前会先按**文本相似度**核对已拒绝记录（同一条事实的两种说法也要认得出来），
  命中就跳过，并在日志里如实注明"因为用户拒绝过同类而没有写入"。
- 自动提取现在会判断「这条是不是用户**明确要求**记住的」：是 ⇒ 跳过上面的判定、可以替换已有的自动记忆、
  并且**直接生效**（不再进待批准）。判断拿不准时一律按"需要批准"处理，不会替你表态。
- 记忆体检新增「已拒绝」一节：显示条数、最近 10 条（标题 + 作用域 + 时间 + 正文摘要），
  以及「清空已拒绝记录」。
- 删除一条**已经生效**的记忆不算"拒绝"（那只是不想要这一条了），不会连带封掉同类事实。

### 修复

- 无。

## 对标结果

**本版未重跑对标评测**，沿用上一稳定版的结论：在 **12 个真实仓库修复任务**上，本版通过 **10 个**，
参考实现（DSH，同一套任务、同一模型）通过 **9 个**；完成同样任务所需的工具调用约为参考实现的一半，
输出 token 用量明显更少；单次响应时延仍慢于参考实现（取决于模型服务端，客户端侧不是瓶颈）。

本版改动全部落在**记忆的写入判定与展示**上，没有触碰 agent 循环、工具链路与提示词主链路，因此沿用上面的数字。

## 升级说明

- 覆盖安装即可，无需手动操作；已有的会话、记忆、待批准条目与各项设置原样保留。
- 已经拒绝过的旧记录无法追溯（以前没有留痕），从本版起新发生的拒绝才会计入。

## 已知问题 / 后续

- 「已拒绝」的判定是**按内容跨项目**生效的：你在某个项目里拒绝过的一类事实，在另一个项目里也不会被自动
  写入（这是刻意的：你说了不要再问，就不再问）。若确实想在别处记下来，**在对话里明确要求记住**即可；
  或者到「记忆体检 → 清空已拒绝记录」把这类封禁解除。
- 判断「这句话算不算用户明确要求记住」由模型完成：极少数含糊表述（例如只是在讨论"记忆"这件事本身）
  可能被记成需要批准。拿不准时它不会替你放行。
- 一条自动记忆被「拒绝」等于删除它，没有逐条的"恢复"入口；恢复的方式是清空已拒绝记录后再让它被重新提取。
