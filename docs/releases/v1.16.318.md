# Codem v1.16.318

**发布日期**：2026-10-13
**类型**：稳定版（Windows x64）
**下载**：`Codem_1.16.318_x64-setup.exe`（NSIS 安装包）· `Codem_1.16.318_x64_en-US.msi`（MSI）

## 本版要点

1. **插件「起不来」时的提示，现在说的是真原因，而且能一键修好**
   - 你报的那句提示里有三处不对：那张卡片其实在「插件管理 → **Our Free Model**」（「插件市场」是另一个页签）；
     Node 你早就装着；最要紧的是**没告诉你真原因**。
   - **真原因**：上一次运行留下的插件进程**还在运行并占着它的数据目录**，于是新实例一起来就退出，
     18937 端口上永远没有服务。
   - **现在**：提示会**引用插件自己日志里的原话**，并点出是哪个进程号占着（例如「进程号 5820」）；
     启动时 Codem 会**先结束那个残留进程、再重新启动插件**（一次就起来）；插件卡片上还多了一颗
     「**结束残留进程并重试**」，随时可以手动来一次。
     —— 它**只结束属于本插件的那个进程**：读不出那个进程的身份就不动手，所以不会误杀别的程序。
   - 「暂停」现在也会真的把上一次留下的实例收掉（以前界面说「已暂停」，那个进程其实还在服务）；
     卡片也会如实标注「（上一次启动的实例）」，不再出现"卡片说没起来、模型列表里却有免费模型"的自相矛盾。
2. **压缩上下文现在「看得见」**
   - 你报的：点了「压缩上下文」，**没出现进度、也没出现压缩提示** —— 很容易让人以为没压缩而重复点。
   - **原因**：压缩本身很快，而「压缩中」的那一帧**从来没有被画到屏幕上**；结果提示只显示 **3 秒**就消失；
     更糟的是重复点**真的会再压一次**（第二次删掉的是刚保留下来的那批消息）。
   - **现在**：点下去立刻显示「⏳ 压缩中…」并禁用按钮；完成后有一条**常驻回执**，
     写明「移除 N 条旧消息，保留最近 M 条；本对话里已插入一条 `[上下文已手动压缩]` 摘要」；
     随后 **8 秒内按钮不可点**并显示「✅ 已压缩（移除 N 条）」。
   - 如果这次**没有可移除的消息**，回执也会说清为什么（可见消息不足 20 条时不压缩；
     上下文占用主要来自系统提示与工具定义，压缩对话不会让它降下来）。

## 变更

### 修复
- 插件启动失败的提示：位置指错、动作给错、真原因缺失；由残留进程导致的「永久起不来」现在能自愈，也可一键处理。
- 「暂停」对"上一次留下的实例"不生效（界面说停了，服务其实还在答）。
- 插件卡片把"接手来的实例"误报成「已启用，尚未启动」。
- 压缩上下文缺少进度与结果反馈、结果提示 3 秒后消失、重复点会重复压缩。

## 对标结果

本版未重跑对标评测，沿用上一稳定版的结论：在 **12 个真实仓库修复任务**上，本版通过 **10 个**，
参考实现（DSH，同一套任务、同一模型）通过 **9 个**；完成同样任务所需的工具调用约为参考实现的一半，
输出 token 用量明显更少；单次响应时延仍慢于参考实现（取决于模型服务端，客户端侧不是瓶颈）。

本版改动集中在免费模型插件的启动诊断与上下文面板的反馈，没有触碰 agent 循环与工具链路。

## 升级说明

- 覆盖安装即可；已有的会话、记忆、待批准条目、供应商与设置原样保留。
- 如果你还停在 1.16.310 / 1.16.311：升级时可能弹出「无法打开要写入的文件：…\resources\node\node.exe」，
  遇到时请**先完全退出 Codem 再装**，或点 **[Ignore]**（别点 [Retry]）。
- 若升级后仍看到插件没起来的提示：打开 **插件管理 → Our Free Model**，
  点卡片上的「**结束残留进程并重试**」即可。

## 已知问题

- **免费模型池是第三方公开网关**（不是 Codem 的服务器）：上游按自己的政策随时上下线模型 ——
  例如它自家的免费车道现在只允许它自己的客户端使用，这类模型会被标记为不可用并从列表里隐藏。
  可用性结论**带时间戳、30 分钟后自动失效**（上游恢复后模型会自己回到列表），
  也可以点插件卡片上的「检测可用性」重新检测。
- **部分免费模型的模态信息上游没有提供**，界面上显示【未知】—— 我们不用名字猜；
  要变确定需要实测（发一张极小图片看接口是否接受图像输入）。
- 免费池的模型卡里声明"提示词可能被记录并用于改进服务"——**请不要用它发送敏感内容**。
- 退出时的「卡一下 / 要按两次」：此前已把退出路径上的同步等待改成"发出去不等"，
  但**尚未在真机上完成端到端计时确认** —— 如仍遇到请反馈现象。
