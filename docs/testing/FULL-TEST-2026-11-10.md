## 已修复的测试问题

### R1（已修复）Rust 网关测试断言过期

```text
phone::gateway::tests::rpc_requires_pairing_and_forwards_only_the_whitelist
assertion left == right failed: 未实现的方法不得到达渲染层
left: 17  right: 16
```

- 根因：测试先断言 `fake.calls()==17`，随后又写死期望 `16`；网关实际没有转发未实现方法。
- 修复：改成“调用前快照”，断言两个未实现方法前后 `fake.calls()` **不增加**；不再绑定会随白名单演进变化的固定数字。
- 结果：`cargo test` **261 passed / 0 failed / 6 ignored**。

### R2（已修复）两条全量并行偶发红

- `FT-WIRE-3`：stub 的 `execute_command` 返回 git status，桌面文件树异步刷新后多一个 badge，而共享 FileTree 的 entries 没有 gitStatus ⇒ outerHTML 偶发不等。修复：该判据只比较文件树 DOM，stub 固定返回空 git status。
- `MEM-IPC-1b`：400 条记忆的整份 payload 测试在满载并行下超过默认 5s。修复：用例超时设为 20s。
- 结果：全量 **966 files / 10168 passed / 18 skipped / 0 failed**。

### R3（观察，非产品缺陷）真实模型超大历史连续回合

- deepseek-chat + 95K input 的会话，首个完成回合成功 switch；
- 随后连续发送测试消息时出现 37 条 compact markers，耗时约 1 分钟；
- 首个 switch 已成立；该会话由直接 DB 种子 + 多次测试发送构造，不作为产品缺陷判定，但“超大历史 + 连续回合”的成本/延迟需要后续单独观察。
