## 2. NotebookLM 布局与交互深度分析

### 2.1 整体布局架构

NotebookLM 采用经典的 **三栏布局**，每栏可独立折叠，核心设计理念是「**对话为中心，来源和笔记辅助**」。

### 2.2 左栏：Sources Panel

**布局特征**：
- 固定宽度 ~280px，可折叠为图标条
- 顶部「+ Add Source」大按钮，多来源类型下拉（PDF/Text/URL/Google Docs/YouTube/Audio）
- 来源列表项 = 图标 + 名称 + 摘要预览（2 行）
- 每个来源前有 **勾选框 (Checkbox)**：控制该来源是否参与对话检索
- 来源卡片可展开查看自动摘要

**关键交互**：
| 交互 | 行为 |
|------|------|
| 点击「+ Add」 | 弹出来源类型选择器 |
| 勾选/取消来源 | 实时影响对话检索范围 |
| 点击来源卡片 | 展开显示来源摘要 + 关键话题 |
| 悬停来源卡片 | 显示删除/重命名操作 |
| 拖拽文件到面板 | 直接上传作为来源 |

### 2.3 中栏：Chat Area

**布局特征**：
- 占据最大空间（弹性宽度）
- 顶部：笔记本标题 + 「Studio」下拉按钮 + 「Share」按钮
- 空状态：3 个建议问题卡片（可点击直接提问）
- 对话流：用户消息 + AI 回答（含引用标注）
- 底部：固定输入框

**引用标注设计**（NotebookLM 最强特色）：
```
AI 回答示例：
"The API supports both REST and GraphQL endpoints [1].
Authentication uses OAuth 2.0 with bearer tokens [2].
Rate limiting is set at 1000 requests per hour [1][3]."

     [1] [2] [3] = 可点击的引用标记
     点击 → 左栏对应来源高亮 + 滚动到原文位置 + 高亮文本片段
```

**Studio 下拉菜单**（内容生成入口）：
```
┌─────────────────────────┐
│ Studio                  │
├─────────────────────────┤
│ 📄 Briefing Doc         │ → 生成结构化简报
│ 📚 Study Guide          │ → 生成学习指南
│ ❓ FAQ                  │ → 生成常见问答
│ 📅 Timeline             │ → 生成时间线
│ 🧠 Mind Map             │ → 生成思维导图
│ 🎙️ Audio Overview       │ → 生成播客音频
└─────────────────────────┘
```

### 2.4 右栏：Notes Panel

**布局特征**：
- 固定宽度 ~300px，可折叠
- 顶部「+ Add Note」按钮
- 笔记列表：卡片式，显示标题 + 内容预览
- 两种笔记来源：
  1. **用户手动创建**：点击「+」创建空白 Markdown 笔记
  2. **从 AI 回答保存**：AI 回答下方有「Save to Note」按钮
- 笔记可编辑、删除、固定置顶

### 3.2 左侧 Ribbon（垂直图标栏）

Lumina Note 的 Ribbon 是最窄的导航条（~48px），从上到下排列图标：

| 图标位置 | 功能 | 说明 |
|---------|------|------|
| 1 | 🔍 Search | 跨 Vault 全文搜索 |
| 2 | 🤖 Bot | 打开/关闭 AI Chat 面板 |
| 3 | 📁 Files | 打开/关闭文件树 |
| 4 | 🖼️ Images | 浏览 Vault 中所有图片 |
| 5 | 🌐 Network | 打开知识图谱全屏视图 |
| 6 | 🧩 Puzzle | 管理已安装插件 |
| — | — | — |
| 底部 | ⚙️ Settings | 设置面板 |
| 底部 | ☀️/🌙 | 亮/暗主题切换 |
| 底部 | ⬇️ | 检查更新 |

**Ribbon 设计要点**：
- 始终可见，宽度仅 ~48px
- 图标有 tooltip 悬停提示
- 当前激活的面板图标高亮
- 点击同一图标第二次 = 关闭面板

### 3.3 文件树 + 编辑器主区

**文件树**：
- 标准 macOS Finder 风格的树形结构
- 显示 Vault 文件夹下的所有文件
- 支持 .md、.txt、.pdf、图片等
- 点击文件 → 主区域打开对应编辑器/查看器
- PDF 文件 → 内置 PDF 阅读器接管主区域

**Markdown 编辑器**：
- 基于 CodeMirror 6
- 三种模式切换：
  - **Live Preview**：编辑 + 实时渲染（默认）
  - **Reading Mode**：纯阅读渲染
  - **Source Mode**：纯 Markdown 源码
- 支持的功能：
  - 语法高亮（代码块）
  - LaTeX 公式渲染
  - WikiLinks `[[笔记名]]` 自动补全 + 悬停预览
  - 图片内联显示
  - 表格渲染

**选中文本浮动工具栏**（Selection Toolbar）：
```
当用户在编辑器中选中文本时：

  ┌──────────────────────────────────┐
  │ 选中的文本内容...                   │
  └──────────────────────────────────┘
  ┌──────────────────────────────────┐
  │ [🤖 Send to AI] [📋 Flashcard]   │ ← 浮动工具栏
  └──────────────────────────────────┘
```

### 3.4 AI Chat 面板

- 右侧可折叠面板（~380px）
- 两种模式：
  - **Chat 模式**：自由对话
  - **Plan 模式**：AI 先制定计划，用户确认后执行
- 支持 Slash Commands：`/` 触发命令菜单
- AI 可直接编辑文件（通过 opencode SDK）
- 工具栏：导出当前对话

### 3.5 知识图谱

- 全屏力导向图（Force-directed Graph）
- 节点 = 笔记文件
- 边 = WikiLinks 关系
- 可拖拽、缩放
- 点击节点 → 跳转到笔记
- 有「全局图谱」和「当前笔记局部图谱」两种视图

### 3.6 命令面板

- `Ctrl/Cmd + P` 触发
- 类似 VS Code 的 Quick Open
- 搜索文件、执行命令、切换设置

## 4. 我们当前 UI 的问题诊断

### 4.1 架构问题

| # | 问题 | 严重度 | 说明 |
|---|------|--------|------|
| 1 | **模态弹窗隔离** | 🔴 严重 | 笔记本是 900px×80vh 的模态弹窗，与主应用完全隔离，无法同时查看对话和来源 |
| 2 | **单视图切换** | 🔴 严重 | 列表→详情是对栈式导航，无法同时看到来源、对话、笔记 |
| 3 | **对话不在笔记本内** | 🟡 中等 | 「开始对话」关闭弹窗后回到主面板，用户丢失笔记本上下文感 |
| 4 | **无笔记面板** | 🔴 严重 | 完全没有笔记创建/编辑/管理的 UI 入口 |
| 5 | **无来源预览** | 🟡 中等 | 来源列表只显示名称和状态，无法预览内容 |
| 6 | **无来源选择控制** | 🟡 中等 | 对话时无法选择使用哪些来源 |
| 7 | **引用不可点击** | 🟡 中等 | `[Source: name]` 是纯文本，无法跳转到原文 |
| 8 | **无内容生成入口** | 🟡 中等 | 没有 Studio 式的内容生成快捷入口 |

### 4.2 操作流问题

```
当前用户流程（断裂式）：

  打开笔记本弹窗 → 选择笔记本 → 查看来源 → 点击「开始对话」
                                                    ↓
  弹窗关闭 ← 回到主面板 ← 进入笔记本模式对话 ← 上下文丢失！

  想看来源？ → 重新打开弹窗 → 来源列表（但对话被覆盖）
  想看笔记？ → 无此功能
  想生成简报？ → 无此功能
```

**对比 NotebookLM 的流程**（连贯式）：
```
  打开笔记本 → 三栏同时可见 → 添加来源 → 对话 → 保存笔记 → 生成简报
                              ↓            ↑          ↑          ↑
                          左栏可见      中栏对话    右栏笔记   Studio 菜单
```

### 4.3 当前 CSS 布局分析

当前 `NotebookManager.tsx` 的核心问题在于它是被渲染在一个 `modal-overlay > modal-editor` 容器中：

```tsx
// App.tsx 中的渲染方式
{showNotebookManager && (
  <div className="modal-overlay" onClick={() => setShowNotebookManager(false)}>
    <div className="modal-editor" style={{ maxWidth: '900px', height: '80vh' }}>
      <NotebookManager ... />
    </div>
  </div>
)}
```

这意味着笔记本管理是一个**临时的模态覆盖层**，而非一个**持久的工作区**。

### 9.2 关键架构决策

**决策 1：笔记本工作区作为路由级页面 vs 模态弹窗**

```
方案 A（推荐）：路由级页面
  /notebooks          → 笔记本列表页

方案 B：全屏覆盖层
  点击笔记本 → 全屏覆盖三栏布局 → 返回按钮回到列表

  优点：改动最小
  缺点：不是真正的路由
```

**决策 2：中心区 Chat 和 Editor 的关系**

```
方案 A（推荐）：Tab 切换
  [💬 对话] [📝 编辑]
```
