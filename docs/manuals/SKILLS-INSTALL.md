# Codem 技能安装手册（权威）

> **给模型看的纪律**：装技能**先读完本文**，照 §2 的五步做。
> 本文与系统提示里那段「Skill environment」是**同一份事实**（出处：`src/core/skill/skill.ts::buildSkillEnvironmentSection()`），
> 二者冲突时以代码里那段为准 ✓。**不要逐仓试探** ✗ —— 那是被浪费的 token。

## 1. 布局（唯一被识别的形状）

```
<技能根>/<技能名>/SKILL.md      ← 一个技能 = 一个目录 + 一个 SKILL.md（+ 它自己的脚本/资源）
```

- `<技能根>` 有两个（**都由应用在启动时给出真值**，见系统提示里的「Skill environment」段）：
  - **用户级**：`<应用数据目录>/.codem/skills/`（对本机所有项目生效）
  - **项目级**：`<项目根>/.codem/skills/`（只对该项目生效）
- `SKILL.md` 以 **YAML frontmatter** 开头，**必填** `name` 与 `description`；
  `name` 用 **kebab-case**（如 `office-docx`），**目录名与它一致最省事** ✓
- **发现是自动的**：目录符合上面的形状就会被加载 —— **没有注册步骤、没有清单文件要改** ✓
- 反例 ✗：技能根下名为 `SKILL.md` 的**目录**会被判结构异常并跳过（别把文件放成同名目录）。

## 2. 从仓库/URL 安装一个技能（照这个做，不要试探）

1. **先定位仓库里的技能目录**：
   - 仓库根就有 `SKILL.md` ⇒ **整仓就是一个技能**；
   - 否则找 `skills/<名>/SKILL.md`、`.agents/skills/<名>/SKILL.md`、`.claude/skills/<名>/SKILL.md` 等。
2. **只把"那一个技能目录"**（含它自己的 `SKILL.md` 与脚本）复制到用户级技能根：
   `<用户级技能根>/<技能名>/`
   —— **不要整仓拷进去** ✗（仓库里的 README、测试、CI 不是技能的一部分）。
3. **取文件只用 `git clone`（或下载 zip 解压）**；
   **不需要**任何安装器、**不需要**改配置 ✓。
4. **验证**：读回 `<用户级技能根>/<技能名>/SKILL.md`；
   能读到且 frontmatter 有 `name` / `description` ⇒ 装好了 ✓。
5. 装好后它会出现在技能列表/提示里的技能目录中；
   若这一轮还没出现 ⇒ 让用户**重启应用**或等下一次重扫 ✓ —— **不要重复装** ✗。

## 3. 卸载

删掉 `<技能根>/<技能名>/` **整个目录** ✓。
（应用内也有卸载入口：`src/core/skill/installer.ts::uninstallSkill`，它会先做路径守卫再永久删除 ✓。）

## 4. 应用内安装（用户操作，不是模型操作）

- ZIP 安装：用户选/拖一个含 `SKILL.md` 的 ZIP ⇒ `installSkill` 在前端解压并写入技能根
  （安全限制：拒绝 `..` 与绝对路径、最多 100 个文件、单文件最大 1 MB、仅常见文本/资源扩展名 ✓）。
- 市场安装：`src/core/skill/skill-market-client.ts`（可按仓库 + 子目录安装 ✓）。

模型**不要**自己去做这两件事（那是 UI 里的操作）；模型要装技能就照 §2 复制目录 ✓。

## 5. 与技能相关的已知坑

- **别把技能装到插件目录**：技能与插件是两套机制 ⇒ 插件见 `docs/manuals/PLUGIN-INSTALL.md` ✓。
- **技能名重复**：同名技能会互相覆盖/歧义；装之前先看技能列表里有没有同名 ✓。
- **`SKILL.md` 编码**：UTF-8；带 BOM 的 JSON/配置会让解析炸（本仓构建被 BOM 搞挂过一次，判据 `BOM-1` 在守 ✓）。
