## 3. 三条主动脉（理解"关系"的关键）

### 3.1 插件：**注册 ≠ 生效**（最容易踩的坑）

- 有两个入口，只有一个是真的：
  - `src/core/plugin-loader/builtin-registry.ts::registerBuiltinPlugin()` → **只填注册表**（插件管理器/可达性门禁能看见，但**不提供任何服务**）；
  - `config/codem.base.yml`（+ `codem.desktop.yml` 覆盖层）→ `mergeYamlEntries()` → `loadFromEntries()` → `ctx.plugin()` → **这才是 apply**。
- 契约：`const p: Plugin = (ctx) => ctx.provide('<service>', {...})`；消费者用 `getToolContext()?.get('<service>')`。
- YAML 的 `when:` 是**平台条件**（`when: platform == 'win32'`），解析器必须容忍引号。
- 判据：`SO-6`（清单与注册表双向对账）、`SO-8`（零例外全量对账，白名单已整块删除）、`plugin-assembly-path.test.ts`。
- **历史教训**：曾经有插件只注册没装配，单测全绿但真机功能永不生效（226 波翻车）。改插件相关代码后**必须**确认清单里有声明。

### 3.2 设置与凭据：**凭据是封存的**

- 存储：DB 的 `settings` 表（`codem-settings` 是一整块 JSON）；扁平键（如 `codem-deepseek-web-search`）单独存。
- **凭据形态**：`providers[].apiKey` 落盘时被替换为 `apiKeySealed`（密文，形如 `dsh1:…`），明文 `apiKey` 是**空串**；
  读取时由设置层**水合**回明文。
  ⇒ **绝对不要用"原始库里的 apiKey 是空"判断用户没填 Key**（本会话我就这么误判过一次，向用户更正了）。
- 写收口：`src/core/storage/settings.ts` 的 `setSetting / setSettingJSON`（唯一收口；里面还有"写回闸门"防止读改写把明文重新落盘）。
- 面板保存：`SettingsPanel.tsx::handleSave()` —— 它做四件事：`buildSavePayload()`（以**保存那一刻的库值**为基座 + 只覆盖面板真正改过的字段，见 `dirtyLocalFields`）、
  `beginSettingsWriteProbe()/flushSettingsWrites()`（**可等待的写后确认**，失败如实显示"未确认保存"）、凭据封存、`codem-settings-changed` 事件。
  ⇒ 任何"保存"按钮都必须走它，**裸 `setSettingJSON({...settings})` 是假保存**（本会话修过一颗）。
- 判据：`SKEY-2`（每个设置键既有写方又有读方）、`SAVE-REFRESH-1/2`（保存按钮必须走规范路径 + 真刷新）、`SETTINGSORDER-197-*`。

### 3.3 存储与数据根

- 引擎：Rust 自研 SQLite（WAL），库文件 `%APPDATA%\com.codem.app\codem-db-rust.bin`（+ `-wal` / `-shm`）。
- 数据根解析（`src-tauri/src/storage.rs`）：
  - **`CODEM_DATA_HOME`** = 显式重定位**整个数据根**（sessions/attachments/spill/.codem），未设时**逐字节等价**于旧行为；
  - **`CODEM_DB_PATH`** = **只**决定库文件位置，**不**连带搬 dataHome（交接里旧说法是错的，已在 HANDOFF 加更正）；
  - `app_data_dir_path()` 是 `app.path().app_data_dir()` 的**唯一**调用点（别新增第二处）。
- **只读钻取**：必须用 `tools/maintenance/read-only-db.mjs`（复制 `.bin`+`-wal`+`-shm` 到临时目录再读，读完删，前后指纹复核）。
  直接只读打开真库会更新 `-shm` 的 mtime（内容不变但仍是痕迹），判据 `RODB-231-*` 守着。
- Rust 契约金样本：`src-tauri/codem-db/tests/wire_contract.rs` 生成 `wire-fixtures.json`；
  `WIRE-0` 检查"最近是否真跑过 Rust 侧"——它读**不入库**的 `wire-fixtures.verified.json`（每次 `npm run db:test` 重写）。

### 3.4 工具系统（加工具要动的 4 个地方）

1. `src/core/llm/tools/<name>.ts` 实现工具（`ToolDef` + `execute`）；
2. `src/core/llm/tools.ts` 里 `registry.register(createXxxTool())`；
3. 若要可并发：加进 `concurrency-policy.ts::CONCURRENCY_SAFE_TOOL_IDS`（**只读、无副作用**才可）；
   注意 `tool-concurrency-list.test.ts` 有一张"幽灵名"反回归表 —— 新工具若曾在那张表里，要**改成正向断言**；
4. 输出契约：`outputSchema` + `renderOutput` **共用同一个渲染函数**（避免文本/契约漂移）；有 `output-schema-ratchet` 基线会检查工具数。
   此外新增上报点要在 `tools/audit/report-site-classification.json` 登记（闸门要求三数相等）。

### 3.5 记忆管线（本会话改得最多）

```
回合结束 → extractMemoriesFromSession (src/core/llm/index.ts)
  → 候选（每批最多 2 条）
  → 同批同主题合并（candidate-merge.ts，scope 取组内**最严**，提升写 scopePromoted）
  → 待批准积压闸门（pending-backlog.ts：全局上限 5 条）
        超限 ⇒ 降级为 conversation 级（直接生效、不打扰），并打 demotedFrom 留痕
  → 面板：待批准列表（可滚动）+ 「本会话已自动降级 N 条（查看）」+ 「其它项目还有 N 条待批准」
```
- 关键语义：`memoryScopeFromExtraction` 只有 `project|platform` 走"需批准"；其它走 conversation（**直接生效**）。
- 判据：`MEMP-1..8`、`MEMC-1..5`、`MEM-DEMOTE-1..4`、`MPS-231-*`、`MB-UI-*`、`MOP-*`。

**并行纪律（多人/多 agent 同时改这个仓库时）**
- **只按 PID 杀自己 spawn 的进程**（`Start-Process -PassThru` 取 PID → `taskkill /PID <pid> /T /F`）。
  **绝对不要 `taskkill /IM codem.exe`** —— 上一会话就是这么把另一个 agent 的实例带走的。
- 真机/构建持锁：`mkdir .preview-shot/_realmachine.lock`，用完 `rmdir`；锁超过 30 分钟可接管。
- **禁止整树 git 操作**（`git stash` / `checkout -- .` / `reset --hard`）；只 `git add <显式路径>`。
- 推送：`git -c credential.helper= -c credential.helper='!gh auth git-credential' push --porcelain origin master`（默认 helper 会挂）。
- 一条命令跑完**必须用文件内容/退出码复核**（并行时 `ops_bash` 的 stdout 会串台）。

## 7. 陷阱清单（会让你得出**错误结论**的那种，按危险度排序）

1. **凭据是封存的**：读原始库 `apiKey` 为空 ≠ 用户没填。要判断有没有 Key，走设置层水合（或在应用里读）。
2. **注册 ≠ 装配**：只在 `builtin-registry.ts` 注册插件，功能不会生效，但单测可能全绿。见 §3.1。
3. ~~**`docs/*.md` 不入库**~~ **这条是错的（2026-10-17 晚更正）**：`docs/HANDOVER-2026-10-17.md`、
   `docs/HANDOFF-NEXT-SESSION.md`、`docs/NEW-SESSION-START.md`、`docs/PROJECT-GUIDE.md` 全部**已被 git 跟踪**
   （`git ls-files docs/` 与 `git check-ignore -v` 都能当场证否）。所以对它们的编辑**必须提交**，
   否则下一个会话 pull 不到、工作区还会一直挂着未提交改动。别再照着旧说法"改了就留在工作区"。
4. **`stripComments` 之后注释消失**：任何"用注释当切片锚点"的判据都会 `indexOf=-1` ⇒ 圈进文件尾部 ⇒ **恒红**（本会话修过 `audit184 F1e`）。
5. **日历炸弹**：判据读"某时间戳距今多久"时，生成器若"内容不变就不刷新时间戳"，到期必红且提示的修法无效（本会话修过 `WIRE-0`：改成单独的验证戳）。
6. **全量并行下偶发抖动**：计时敏感用例（整树扫描类）满载时会超时，**先单跑确认**再判断是不是回归。
7. **`Set-Content -Encoding UTF8`（PS 5.1）会写 BOM**：会炸 JSON/PostCSS。命令一律走 `@codem/shell-ops`（默认开，真 bash）。
8. **脚本内容错误的三种死法**（与 shell 无关）：模板串里嵌反引号、块注释里出现 `*/`、中文串里混半角引号。写完**立刻** `node --check`。
9. **`ops_bash` 里 `/tmp` 与 Node 的 `/tmp` 不是同一目录**（MSYS vs C:\tmp）：跨两者传临时文件会失败（我就因此把变异留在源码里过一次，靠 `git checkout --` 救回）。
10. **不要用"目标模式/自动续跑"开发本项目**（AGENTS §5.9 明令禁止）：一次把事做完，多步用清单，岔路直接问用户。
11. **Windows 文件名大小写/长路径**：不要在 `src/test` 里造超长路径夹具；`tar` 解包用统一正斜杠。
12. **同名"保存"按钮**：面板里有多个保存入口，只有 `handleSave` 是规范路径；其余可能只是"刷新模型"或"立即生效的选项"。
