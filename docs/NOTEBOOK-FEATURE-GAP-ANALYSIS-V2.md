## 一、B 类问题：有代码无入口 / 交互断链（7 项）

### B14: 知识图谱节点点击无响应 ⚠️ 高优先级

| 项目 | 详情 |
|------|------|
| **对标** | Lumina Note Graph View — 点击节点跳转到关联笔记 |
| **现状** | `KnowledgeGraphView` 组件定义了 `onNodeSelect` 回调 prop，但 `NotebookWorkspace` 渲染时**未传递该回调**：`<KnowledgeGraphView notebookId={notebookId} />` |
| **影响** | 用户在图谱中选中节点后，右侧面板能显示节点详情，但无法跳转到相关笔记或创建新笔记 |
| **涉及文件** | `NotebookWorkspace.tsx` L542, `KnowledgeGraphView.tsx` L26-28 |
| **修复方案** | 传递 `onNodeSelect` 回调，点击节点时查找匹配笔记并打开编辑器，或提示创建新笔记 |

### B15: 引用标注格式不统一 — 工具端 vs 展示端 ⚠️ 高优先级

| 项目 | 详情 |
|------|------|
| **对标** | NotebookLM — 引用统一格式 `[N]` 可点击 |
| **现状** | `search-notebook.ts` 工具返回格式为 `[Source: name]`，但 `MessageBubble` 的正则匹配 `[Source N: name]`（带数字编号）。LLM 生成回答时可能使用不同格式，导致引用不被识别 |
| **影响** | 部分引用无法被正则匹配，不会变为可点击链接 |
| **涉及文件** | `search-notebook.ts` L75, `MessageBubble.tsx` L184 |
| **修复方案** | 统一引用格式，或放宽正则匹配模式以兼容多种格式 |

### B16: 工作区「对话」Tab 无实际聊天能力

| 项目 | 详情 |
|------|------|
| **对标** | NotebookLM — 工作区内直接对话 |
| **现状** | `NotebookWorkspace` 的 `viewMode === 'chat'` 只显示建议问题和「开始对话」按钮，点击后跳转到 App 主聊天界面，工作区本身没有内嵌聊天 |
| **影响** | 用户需要离开工作区才能对话，体验割裂。NotebookLM 是在同一界面内对话 |
| **涉及文件** | `NotebookWorkspace.tsx` L507-512, L617-660 |
| **修复方案** | 在工作区 chat tab 中内嵌 `ChatPanel` 组件，或改为用 iframe 方式嵌入 |
| **优先级** | P2 — 体验提升 |

### B17: AI 工具 `delete_note` 未注册

| 项目 | 详情 |
|------|------|
| **对标** | Lumina Note — AI 可完整管理笔记 CRUD |
| **现状** | `note-operations.ts` 注册了 `create_note`、`edit_note`、`link_notes` 三个工具，但缺少 `delete_note`。存储层 `deleteNote` 函数已实现 |
| **影响** | AI 无法删除笔记，只能创建和编辑 |
| **涉及文件** | `note-operations.ts`, `storage.ts` (deleteNote 已存在) |
| **修复方案** | 在 `note-operations.ts` 中新增 `delete_note` 工具定义 |

### B18: 闪卡 AI 生成使用 FAQ 类型，未使用专门的闪卡 prompt

| 项目 | 详情 |
|------|------|
| **对标** | Lumina Note — 从笔记内容直接生成闪卡 |
| **现状** | `FlashcardViewer` 的 `handleAIGenerate` 调用 `generateStudioContent(notebookId, 'faq')`，复用 FAQ 的 prompt 来解析 Q/A 对。但 FAQ prompt 的格式不一定能可靠解析为闪卡 |
| **影响** | AI 生成的闪卡可能格式不对，解析失败时静默跳过 |
| **涉及文件** | `FlashcardViewer.tsx` handleAIGenerate |
| **修复方案** | 新增专门的 `generate_flashcards` 函数，使用专门的闪卡生成 prompt（Q: ... A: ... 格式） |

### B19: 笔记搜索/过滤仅有标签，缺少全文搜索

| 项目 | 详情 |
|------|------|
| **对标** | NotebookLM — 笔记列表支持全文搜索 |
| **现状** | 笔记列表仅有标签筛选栏，无搜索框。用户无法按关键词搜索笔记标题或内容 |
| **影响** | 笔记数量多时难以定位 |
| **涉及文件** | `NotebookWorkspace.tsx` 笔记面板区域 |
| **修复方案** | 在笔记列表上方添加搜索输入框，实时过滤 `notes.filter(n => n.title.includes(q) || n.content.includes(q))` |

### B20: 笔记本管理列表缺少搜索功能

| 项目 | 详情 |
|------|------|
| **对标** | NotebookLM — 笔记本列表搜索 |
| **现状** | `NotebookManager` 列表视图有 `filteredNotebooks` 变量但搜索框仅对来源生效，笔记本列表本身没有搜索框 |
| **影响** | 笔记本数量多时难以定位 |
| **涉及文件** | `NotebookManager.tsx` |
| **修复方案** | 在笔记本列表上方添加搜索框 |

## 三、C 类问题：能力不完整（5 项）

### C1: 引用缺少精确定位（页码/段落）

| 项目 | 详情 |
|------|------|
| **对标** | NotebookLM — 引用标注精确到段落 |
| **现状** | `search-notebook.ts` 返回结果包含 `chunkIndex`，但引用格式 `[Source: name]` 未包含 chunk 编号。点击引用打开 SourceViewer 时也未传递 `highlightChunkIndex` |
| **影响** | 用户点击引用后看到来源全文，但不知道具体引用了哪一段 |
| **涉及文件** | `search-notebook.ts` L75, `App.tsx` handleCitationClick |
| **修复方案** | 引用格式改为 `[Source N: name #chunk]`，点击时传递 chunkIndex 给 SourceViewer |

### C2: PDF 渲染仅在 SourceViewer 中，不支持工作区直接查看

| 项目 | 详情 |
|------|------|
| **对标** | Lumina Note — PDF 嵌入工作区 |
| **现状** | `PdfViewer` 组件已创建，但只在 `SourceViewer` 中使用。工作区来源面板的「查看原文」按钮打开的是 SourceViewer，而非直接嵌入 PDF |
| **影响** | 体验可以更流畅 |
| **修复方案** | 来源面板点击 PDF 来源时直接在工作区打开 PdfViewer |
| **优先级** | P3 — 体验优化 |

### C3: 知识图谱编辑能力缺失

| 项目 | 详情 |
|------|------|
| **对标** | Obsidian — 图谱可手动编辑节点和边 |
| **现状** | 知识图谱仅支持查看、搜索、缩放，不支持手动添加/删除/编辑节点和边 |
| **影响** | 用户无法修正 AI 提取的错误关系 |
| **修复方案** | 支持双击节点编辑标签，拖拽创建边，右键删除 |
| **优先级** | P3 |

### C4: Studio 生成内容无法直接编辑

| 项目 | 详情 |
|------|------|
| **对标** | NotebookLM — 生成的简报/学习指南可直接编辑 |
| **现状** | Studio 生成的内容保存为笔记，可以在 NoteEditor 中编辑。但生成后直接保存，用户无法在生成时预览并选择性编辑 |
| **影响** | 生成内容需要先保存再打开编辑，多一步操作 |
| **修复方案** | 生成后先在预览模式打开 NoteEditor，用户确认后再保存 |
| **优先级** | P3 — 体验优化 |

### C5: 闪卡系统缺少从笔记生成功能

| 项目 | 详情 |
|------|------|
| **对标** | Lumina Note — 从特定笔记内容生成闪卡 |
| **现状** | 闪卡 AI 生成仅支持从整个笔记本生成，不支持从特定笔记生成 |
| **影响** | 无法针对单个笔记创建闪卡 |
| **修复方案** | `FlashcardViewer` 增加 `noteId` 参数，AI 生成时仅使用该笔记内容 |
| **优先级** | P3 |

### 关键发现

1. **引用格式不统一**（B15）是最容易修复但影响最大的问题 — 工具端和展示端的正则不匹配导致部分引用不可点击
2. **知识图谱节点点击**（B14）是一行代码修复 — 只需传递已有的 `onNodeSelect` 回调
3. **工作区内嵌聊天**（B16）是体验提升最大的一项 — 消除工作区与聊天界面的割裂感
4. **YouTube/音频**（A10/A11）仍然是对标 NotebookLM 的最大差距
5. **C 类问题**是新发现的"已实现但不完整"场景，主要影响深度用户体验
