## 0. 两条判定规则（后续所有取舍都用它）

1. **用户零负担**：安装即用；不装运行时、不开系统功能、不配端口、不注册账号、不学新概念。
   凡是把成本转嫁给用户的方案，**直接淘汰**（不做"高级用户可选"的中间形态）。
2. **稳健优先于功能**：宁可少一个能力，也不要"看起来成功其实没做"。
   失败必须可见、可诊断、可回滚；不确定的一律标「未知」，不写「已完成」。

## 1. 已定决策

### D-1 · 回合落库契约：抽 `TurnWriter`，Host 不再自己拼

- **决定**：阶段 1 把 `App.tsx` 的回合落库序列（进入会话时 `hydrateSessionLog` → 建 user 行 →
  assistant 壳 → 工具调用/结果 → 定稿正文 → **同步维护日志镜像**）提取成 `packages/agent`
  的 `TurnWriter`；Host 只调用它。
- **根因（本轮已定位到具体两行）**：
  1. `listMessagesMerged` 在**日志镜像为空**时短路成"只返回索引镜像"（`message.ts:634`）；
  2. `createMessage` 追加磁盘日志，但**不更新 `cachedLogMessages`**，而 Host 的索引镜像又未必就绪
     ⇒ 本回合新写的 assistant/tool 行在循环重建上下文时不存在；`addToolCall` 还只写
     `tool_calls` 索引、不写日志 ⇒ 日志重建时助手行没有 `toolCalls`，工具结果被配对层当孤儿丢掉。
- **代价**：阶段 1 多一个提取动作（约 1–2 天）+ 一条"两端模型请求消息序列一致"的判据。
- **已落地（2026-11，Spike A 6/6、Spike C 8/8）**：
  1. 日志镜像**写穿**（`createMessage`/`updateMessage` 同步维护；裁剪路径同步 `hidden+trimmed`）
     + Host 进入会话先 `hydrateSessionLog`；
  2. `LoopConfig.onToolResult` 钩子：在 `tool_complete` 交给调用方**之前**同步落库
     （循环每轮从存储重建上下文，晚一步就等于模型看不到工具结果）；
  3. **裁剪语义定稿**：默认列表不显示被裁行；「完整历史」用 `listTimelineMessages` 显式展示。
     `SLOG-8` 与 `FIXB-4a` 从此共用同一条规则（前者改为断言 3 条默认 / 8 条完整历史）；
  4. 「不许假成功」守卫：正文为空且跑过工具 ⇒ `run.failed`；
  5. `host.diagnostics.sessionProbe.visibleRoles`：远程可复核"模型会看到哪些角色"。
- **剩余（阶段 1 收尾）**：把上面 1–2 封装成 `packages/agent` 的 `TurnWriter`（现在散在
  `runtime.ts` 与 `message.ts`），并加"同一轮两端请求消息序列一致"的判据。

### D-2 · 事件流用 SSE（不是裸 WebSocket）

- **决定**：`POST /rpc` + SSE `GET /events`；终端（阶段 5）另开 WS，共用同一信封。
- **为什么**：SSE 自带 `Last-Event-ID` 续传（手机切后台/换网最容易出错的地方）、零依赖、
  穿 Tailscale/Cloudflare 更稳。用户侧**零配置**。
- **代价**：单向，请求另走 POST；二进制要 base64（所以终端不用 SSE）。

### D-3 · 许可证：**现在开源**，但只接受可再许可的代码（随时可闭源）

- **决定**：
  1. 项目对外采用 **MIT（或 Apache-2.0）** 这类**宽松许可**；
  2. **任何 GPL / AGPL / 商业不友好许可的代码都不沿用**，发现即**重写**（不是"先搬后换"）；
  3. 依赖只接受 permissive（MIT/BSD/Apache/ISC）；新增依赖必须在 `THIRD_PARTY_NOTICES.md` 登记；
  4. 提交必须能被我方再许可（DCO/CLA 之一）——否则不能合并。
- **为什么**：你要求"当前开源、未来随时可闭源"。只要仓库里存在一行 copyleft 代码，闭源就做不到；
  而"以后再说"会把返工成本推到最坏的时间点（发布前）。
- **代价**：`src/core` 里"参考过外部项目"的文件需要逐个取证；确认是 copyleft 的重写。
  这是阶段 0 的许可证 clean-room 审计交付物，**审计通过前不对外发布新产物**。
- **不需要你读代码**：审计完我给你一张表——「哪些文件是自研 / 哪些重写过 / 哪些依赖是什么许可」。

### D-4 · PC 远程走**桌面网关**，默认关闭、手动启动

- **决定**：PC 远程只由**桌面远程网关**承担（ADR-0005）：设置 → 连接手机里手动「启动网关」，
  手机用 6 位一次性配对码连上，直接读桌面自己的项目/会话/历史。**不默认常驻、不留后台进程**；
  Android 本机模式的 Host 自启只属于手机自己，与 PC 无关。
- **为什么**：用户要“手机能远程”，但也明确“不要默认给我留后台进程”。网关是桌面进程内的 loopback 监听，
  不用时为 0 常驻成本；关闭即撤销全部配对。
- **代价**：远程要用户点一次启动；桌面进程重启/停止网关后需重新配对（HttpOnly cookie 失效）。
- **安全前提**（不因可用而放松）：只绑 `127.0.0.1` 随机端口 + 配对后才接受请求 + `Origin`/`Host` 同源校验；
  手机侧经 adb reverse 或外部通道接入，不开放公网端口。旧 LAN/TLS/二维码配对与 Host sidecar 不再保留。

### D-5 · 单写者租约：后到者接管 + 二次确认

- **决定**：同一会话同一时刻只允许一个客户端发 prompt；手机接管时桌面变只读，
  手机端必须确认一次（提示"桌面正在运行，接管会让桌面变为只读"）。
- **为什么**：两端同时发会让同一会话出现并行回合（丢消息/分支），这是**数据损坏级**风险。

### D-6 · Android 运行时：Ubuntu minimal + 目标 APK ≤ 80 MB

- **决定**：PRoot + Ubuntu minimal（只装 node/git/bash 必需包）；`codem-db` 用静态 musl；
  先量"解包后体积/冷启动/内存"，不达标再换 Alpine。目标 APK ≤ 80 MB。
- **为什么**：Ubuntu 兼容性最好（少踩坑 = 稳健），体积仍可接受；不达标时**改实现**，
  不要求用户清理空间或额外下载。

### D-7 · 配对：网关的 6 位一次性码是唯一用户可见路径

- **决定**：桌面网关的配对（6 位一次性码 + 5 分钟 TTL + 单次使用 + sha256 + 设备上限 8 + 停止即撤销）
  是 PC 远程的**唯一**用户可见配对路径（`src-tauri/src/phone/gateway/pairing.rs`、`gateway_pair_start`、
  `RemoteGatewaySection.tsx`）。Android 本机模式的 `packages/host/src/pairing.ts` 沿用同一套设计，只服务手机本机。
  旧的 `phone-link` LAN 扫码配对（二维码 / 批准 / 设备列表 / cookie / 自签 CA / 中继）已**删除**；
  桌面 Host sidecar 也不再提供配对/远程入口。
- **为什么改**：旧模型把配对和 LAN 传输绑在一起，无法满足"只绑 loopback + 外部通道"的安全边界；
  网关与 Host 已有判据（`host-pairing.test.ts` DPAIR-1..8、`host-authz.test.ts` AUTHZ-1..10、
  `remote-pairing-single-source.test.ts`），继续保留第二套只会让"哪个配对是真的"长期含糊。
- **保留**：`approval-broker`（桌面/微信/AA 共用）与 AA 账号登录；它们不是配对。

## 3. 按"稳健"定下的工程红线（会写进判据）

1. **不假成功**：正文为空 / 工具没执行 / 写入被跳过 ⇒ 必须 `failed` 或显式上报，不许 `succeeded`。
   （已落地：Host 的 run 状态守卫。）
2. **不静默降级**：镜像未就绪、端口未注册、写入被拒 —— 要么启动失败，要么进诊断通道，不许"看起来正常"。
3. **单写者 + 租约**：任何跨设备写都要先拿租约。
4. **默认最小暴露**：只绑 loopback、token + Origin 校验、文件限制项目根、不下发凭据。
5. **禁止第二套实现**：循环、工具、UI 各只有一份；发现分叉即视为缺陷。
6. **可回滚**：Android 运行时保留上一代、桌面更新可回退、数据迁移前有备份与校验。

## 4. 仍需你知情的三件事（不需要技术判断）

1. **许可审计结论**会决定能否闭源发布 APK（法律问题，D-3）。
2. **远程要手动启动**：要远程就在设置里启动桌面网关并生成配对码——这是为了不给你留后台进程（D-4）。
   如果你希望"装完就能远程"，告诉我，我改成默认开启（代价是常驻监听 + 托盘常驻）。
3. **Android 端上性能还没有真机数据**（模拟器是 x86_64，不代表 arm64 真机）。
   阶段 3 第一件事就是量四项指标；不达标我改方案（换更小的 rootfs / 减少常驻），
   不会让你去"多等几秒"或"清理空间"。
