## A. 之前漏掉的两个问题（必须正面解决）

原委派只写了“长程目标模式”，没有把这两个具体问题写成验收项；现在补上。

### A1. 任务做一轮就停

**要求**：Goal 模式里，模型在阶段内以自然语言收尾、但没有 tool call 且**阶段 acceptance 未达成**时，系统必须自动继续当前阶段，而不是等用户点“继续”。

实现要点：

- 在阶段执行器（Goal Runner/阶段 run）里判断：`no tool call + acceptance not met + 未取消/未审批/未阻塞` → 追加一条隐藏的继续指令，**同一阶段、同一 run 上下文**继续；
- 继续指令写权威日志并标记 `autoContinue`，UI 折叠为“自动继续（第 N 次）”；
- 阶段内连续 3 次无进展/重复失败 → 停止该阶段并进入重规划/blocked；
- 不再把“继续”按钮作为 Goal 模式的默认路径；
- 判据：`GOAL-16` 模拟“模型只回文本、没有 tool call”，断言自动发起下一轮且阶段继续；无 pending/acceptance 已达成时不得继续。

### A2. 水位满了 / 单轮超长时压缩会打断任务

**要求**：压缩不能丢目标上下文，也不能把长阶段打断。

实现要点：

- Goal 上下文（契约/计划/当前 phase/acceptance/invariants/最近 evidence）**每轮固定注入**，走尾部易变上下文，不依赖对话历史；压缩不得删除该注入；
- 每个 phase 是持久检查点：压缩前/后写 `goal_phase` 状态与 evidence；压缩后从检查点恢复“当前 phase + 未完成 acceptance”，不重新规划、不重跑已完成；
- 压缩必须保持 assistant(tool_calls) 与 tool 结果成对；若压缩后无法保持，暂停并报 `context_conflict`，不得静默截断；
- 长阶段内压缩后继续执行；如果上下文预算仍不足，明确 blocked，不假装继续；
- 判据：`GOAL-17` 强制在阶段中途触发压缩，断言契约/计划/acceptance 仍在、工具配对完整、阶段继续、无重复副作用；`GOAL-18` 压缩失败/预算不足 → blocked 且原因可见。

## B. 对标改进的追加范围（4 项）

### B1. 手机远程必须能新建会话和项目

**要求**：手机连 PC 桌面网关后，可以：

- 在 PC 桌面**新建会话**（选择已有项目或全局工作区）；
- 在 PC 桌面**新建项目**（项目名 + 目录；目录选择/输入；不能只在手机本地建）。

设计要点：

- 网关新增 `project.list` / `project.create` / `session.create`（协议加方法，不升协议大版本）；
- 数据写入桌面现有库/项目表，不建第二份；
- 新建项目路径校验：绝对路径、存在/可创建目录、工作区边界；路径在桌面允许范围外时走审批或拒绝（产品安全边界要写清）；
- 手机 UI：会话列表“新建会话”恢复；项目选择器 + “新建项目”；创建后直接打开；
- 判据：手机建会话 → 桌面列表出现同一条；手机建项目 → 桌面项目表出现；桌面打开同一会话；非法路径拒绝；断线/重连后仍可见。
- 注意：这补的是 1.17 M2/M4 的 `session.create` 缺口，也涉及项目创建，不是只加一个按钮。

### B2. 开箱无感：配置一次，后续启动不用重复配置

**要求**：首次配对/配置后，桌面重启、手机重连、网关重启都不需要重新配对/手填地址。

设计要点：

- 桌面网关**默认随应用启动**（可在设置关闭），首次启动一次提示；不再要求手动点“启动网关”；
- 配对设备持久化（SQLite/JSON，不只内存）：deviceId/name/token hash/最后在线；重启后 cookie 仍有效；
- 设备列表 + 单设备撤销（替换“停止=撤销全部”）；
- 端口稳定：优先固定/记住端口；端口变化时手机能通过保存的地址/发现机制重连；隧道场景用稳定域名；
- 手机保存上次 host URL + 设备 cookie；自动重连，不再要求扫码/输码（除非撤销/换机）；
- 生成二维码/深链只作为首次便捷入口，不作为每次启动步骤；
- 判据：首次配对后重启桌面 → 手机直接进入、无配对门；重启网关 → 不重配；撤销单设备 → 只该设备回门；关闭自动启动后行为可预期。

### B3. Android 平台缺口：能模拟的必须模拟，不能模拟的要说清

**纠正**：不是“没有 arm64 真机就都不能做”。模拟器可以覆盖大部分；只有 OEM 厂商后台策略/真实相机等需要物理机。

要求：

- 保留 x86_64 模拟器全量 DC；
- 安装 **arm64 Android 系统镜像 AVD**，在 x86_64 主机上以全模拟方式跑（会慢，但可验证 PRoot/Node/DB/WebView 的 arm64 路径）；若当前 SDK 无 API 35 arm64 镜像，用可用 API（34/33）并记录版本差异；
- 原生桥（文件选择/拍照/通知/分享/剪贴板）用模拟器 + fake 数据/MediaStore 验证；通知权限、Doze/电池优化用 `adb shell dumpsys deviceidle` 等验证；
- 厂商后台杀进程、特定 ROM WebView 行为无法可靠模拟 → 用物理机，并在报告里列明“未覆盖的 OEM 项”，不能笼统写“arm64 未验”当阻塞；
- 判据：x86 全量 + arm64 AVD 最小闭环（启动、本机会话、文件、模型设置）+ 原生桥模拟 + Doze 场景；物理机只补 OEM 专项。

### B4. 跨网缺口全部补上

**现实约束**：没有公网入口/中继/账号，纯 loopback 不可能跨网；必须引入一个外部通道。不能假装“自己就能 NAT 穿透”。

要求（按优先级实现，至少两条可用）：

1. **Tailscale**（首选）：检测/引导安装，`tailscale serve`/`funnel` 暴露网关，HTTPS + 稳定域名；桌面一键开启，手机用稳定 URL；配对/cookie 跨重启保持；
2. **Cloudflare Tunnel**：检测 `cloudflared`，支持 quick tunnel（临时）与 named tunnel（稳定，需用户账号/配置）；
3. 通用 **反向代理/自定义域名**：用户已有隧道时，允许配置公开 origin，网关校验 Host/Origin、Secure cookie；
4. 不内嵌自建中继（需要服务器/运维，不在本轮无中生有）。

安全要求：HTTPS、`Secure` cookie、Origin/Host 校验、配对/撤销、只暴露网关必要路径；不能把 loopback 裸奔到公网。

判据：模拟/真实隧道下手机跨网配对→会话→文件；重启后不重配；无隧道时明确提示；错误 origin 拒绝；撤销后 401；文档写清外部依赖与账号成本。
