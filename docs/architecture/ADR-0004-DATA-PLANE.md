# ADR-0004：桌面与 Host 的数据面统一

- 状态：**已被 ADR-0005 取代（Phase 3 取消）**；本文件仅保留 Phase 1 工作区结论作为历史
- 日期：2026-11-02
- 相关：ADR-0001（Host 抽取）、ADR-0002（Android 运行时）、ADR-0003（共享 UI）

## 1. 问题

今天桌面与 Host 是**两套数据面**：

| | 桌面（Tauri 渲染进程） | Host（Node sidecar / Android 本机） |
|---|---|---|
| 数据库 | `%APPDATA%/com.codem.app/codem-db-rust.bin` | `<dataHome>/codem-db-rust.bin`（Android 在 app 私有目录） |
| 权威日志 | 桌面数据根 `sessions/*.jsonl` | Host 数据根 `sessions/*.jsonl` |
| 工作区 | 用户选择的项目目录 | 默认 `<dataHome>/workspace`（桌面 sidecar 是空目录） |
| 会话 | 桌面自己的会话 | Host 自己创建的会话 |

结果：手机连 PC Host 时，**看不到桌面上已有的会话/历史/文件变更**；它只能看到“经 Host 跑过的回合”。
这不符合“PC 是唯一真源”的产品直觉，也是当前最大的功能缺口。

## 2. 约束

1. **不能双写**：SQLite 多写者 + JSONL 追加 + 序号/事件流没有跨进程事务；两个进程同时写同一会话必然产生分叉与静默丢消息。
2. **不能假装**：只读镜像/工作区共享都必须有明确 UX 文案，不能让人以为“手机看到的就是桌面全部”。
3. **单写者租约只在 UI 层**：它约束的是多个客户端抢同一个 Host，不是“桌面进程 vs Host 进程”。
4. **Android 本机 Host 没有桌面进程**：数据面统一只对“手机连 PC”有意义；本机模式天然是 Host 自己的库。
5. **安全边界**：桌面工作区可能含敏感文件；远程读写必须继续走审批/租约，不能因为“同一工作区”绕过。

## 3. 选项

### A. Host 成为唯一写入方，桌面 UI 改为 RPC 客户端（终态，正确）

- 桌面不再直接开 SQLite/JSONL，所有会话/消息/工具/审批经 Host RPC；
- 手机与桌面看到同一份会话、同一事件序号、同一租约；
- 代价：桌面 58k 行 UI + 存储/命令层要大改；Tauri 命令、附件、检查点、文件变更都要经 Host；
- 风险最高，但这是唯一没有“第二真源”的形态。

### B. Host 只读桌面库/日志（镜像历史）

- Host 读桌面 SQLite（WAL 只读连接）与 JSONL，手机可看历史；
- 写入仍发生在 Host 自己的库 ⇒ 历史与新增分叉，必须显式标注“历史只读、Host 新会话独立”；
- 风险：schema/锁/JSONL 半行、隐私（把桌面全部历史暴露给远程设备）、事件序号不连续。

### C. 只统一工作区（文件面）

- Host `--workspace` 指向桌面当前项目；手机与桌面看到同一批文件、同一 git 状态、同一变更；
- 会话/历史仍各自独立；
- 代价小、可逆；必须明确“文件同一份，会话不是同一份”。

### D. 维持现状（两套完全独立）

- 最简单、最安全；但“手机远程桌面”名不副实。

## 4. 决策

**目标形态选 A；近期分两步走：先 C，再评估 B，最后 A。**

1. **Phase 1（现在做 C）**：桌面启动 Host 时把当前工作区作为 `--workspace` 传入；Host 重启后手机看到同一项目文件。UI 明示“文件与桌面同一份；会话列表是 Host 的会话”。
2. **Phase 2（可选 B）**：如果用户需要“手机看桌面历史”，做**只读镜像**：Host 只读桌面 JSONL/SQLite，UI 明确“历史只读”，写入仍进 Host；不合并序号、不双写。
3. **Phase 3（A，终态）**：桌面改为 Host 客户端，删除桌面本地存储写路径；一次性迁移旧库到 Host 数据根。此阶段前不做任何“看起来统一”的假动作。

**明确不做**：双写同一 SQLite/JSONL；用文件监听做“同步”；把桌面 DB 直接指向 Host 进程同时写。

## 5. Phase 1 实施要点（C）

- `host_start` 增加工作区参数（来自桌面当前项目根）；Host 以该目录为 `workspaceRoot`；
- 工作区切换时重启 Host（保留 Host 数据根/会话），手机文件树/变更/diff 立即指向同一项目；
- 安全：写操作仍走审批；Host 仍然只绑 loopback/配对鉴权；
- UX 文案：信息面板显示“工作区（与桌面同一份）”；会话页不暗示历史共享；
- 判据：Host 进程 cwd/参数、`workspace.list` 返回桌面项目文件、桌面改文件手机可见、审批仍生效；
- 回滚：清空该参数即回默认 `<dataHome>/workspace`。

## 6. Phase 3（A）迁移草案

1. 定义 Host 存储 RPC（会话/消息/工具/附件/变更/检查点）；
2. 桌面存储层改为“Host 优先、离线只读缓存”；
3. 一次性导入：桌面库 → Host 库（保留 id/时间戳/JSONL 顺序），校验条数与 seq；
4. 删除桌面写路径与双份 schema 维护；
5. 判据：桌面全量聊天/工具/检查点/搜索判据 + 手机同会话同 seq。

## 7. 后果

- 正向：消除“两个真源”，手机真正远程桌面；租约/审批/事件序号只有一套。
- 负向：Phase 3 工作量大、迁移风险高；Phase 1 必须用文案避免“会话也共享”的误解。
- 未决：桌面工作区路径如何从 Tauri 安全传给 Host（参数 vs 配置文件）、远程设备是否默认允许读写桌面项目（建议默认只读 + 审批升级）。
