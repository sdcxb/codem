# 自主执行（Run-scoped Autonomy）方案

- 状态：**已被 GOAL-MODE-PLAN.md 取代（本文只保留 run-scoped 子集）**
- 日期：2026-11-03
- 关系：取代现状“未完成 todo 只显示一键继续”；不采用持久目标/goal mode
- 目标：用户只给意图与原则，模型在**同一次运行**内自行分析、决策、继续，不再逐步要用户点“继续”

## 1. 一句话

**把“继续”从用户动作变成系统动作，但只在一个 run 内、且有硬预算/硬停止条件；不创建跨会话的持久目标。**

- 用户看到的是一次“开始任务”；
- 中途只有三类事情会打断：**需要审批/不可逆动作、真正缺少关键信息、预算/无进展熔断**；
- 完成后给总结，不再要求用户逐步确认。

## 2. 为什么不是 goal mode

| | 持久目标 / goal mode（禁止） | 本方案（run-scoped autonomy） |
|---|---|---|
| 生命周期 | 跨会话、跨重启一直存在 | 只在本次 `executeSessionTurn` 内 |
| 终止 | 常驻，容易“看起来一直在做” | 每次 run 必然以 done/blocked/budget/error 结束 |
| 恢复 | 自动续跑，难审计 | 应用关闭即停；下次由用户恢复（一次点击） |
| 状态 | 额外全局目标状态 | 复用现有 run/todo/消息，不新增持久目标 |

> 本项目原规则禁止 goal mode 的理由（半成品、自动续跑、可核对性差）仍然成立；本方案用“run 边界 + 硬预算 + 停止矩阵”替代，不恢复持久目标。

## 3. 默认行为（尽量无感）

- **默认开启**（新老会话一致），无需用户逐次选择；
- 纯问答/解释/只读咨询：模型正常收尾，不触发自动继续（没有未完成 todo/计划/验证缺口）；
- 编码/改文件/跑命令类任务：若模型在“还有未完成事项”时收尾，系统自动追加一轮继续指令；
- 用户不需要看到“继续”按钮；只在状态条看到“自动推进 3/20”；
- **审批仍然存在**：需要审批时暂停，用户批准后**自动继续**，不再多点一次“继续”；
- 用户可随时“停止自动推进”或直接发消息干预。

## 4. 触发自动继续的条件（必须同时满足）

1. 当前 run 仍处于活动状态（未被取消/未结束）；
2. 模型本轮**没有 tool call**（自然语言收尾）；
3. 存在结构化未完成信号，至少一项：
   - `todo_write` 中存在 `pending` / `in_progress`；
   - 计划（plan）存在未完成步骤；
   - 本轮有文件改动但验证命令未通过/未执行（可选强信号）；
   - 上一步 tool error 且模型未给出修复/结论；
4. 不在以下“必须停”的状态：待审批、等待用户澄清、预算耗尽、无进展熔断、用户已停止。

> 没有结构化信号时**不猜**“它可能没做完”；宁可正常结束，避免把普通问答变成无限续跑。

## 5. 停止矩阵（硬条件）

| 停止原因 | 触发 | 用户看到 |
|---|---|---|
| `done` | 无 pending todo，且模型给出最终总结 | 正常完成 |
| `need_approval` | 工具请求审批 | 审批卡；批准后自动继续，拒绝则结束 |
| `need_user` | 模型显式调用澄清工具/明确说缺少关键信息 | “需要你补充：…” |
| `irreversible` | 删除/发布/支付/外发等不可逆动作 | 审批/确认；不自动做 |
| `budget` | 轮数/时间/token 达上限 | “已自动推进 N 轮，达到预算；继续一次/调高预算” |
| `no_progress` | 连续 2 轮无文件/todo/验证变化 | “连续两轮没有进展，已停；查看原因” |
| `loop` | 同一工具+参数重复 3 次 | “检测到重复调用，已停” |
| `error` | 连续工具/模型错误不可恢复 | 错误摘要 |
| `cancelled` | 用户停止/关闭会话 | 已停止 |
| `context_exhausted` | 压缩连续失败/预算无法容纳 | “上下文不足，已停” |

## 6. 预算默认值（可配置）

| 项 | 默认 | 说明 |
|---|---:|---|
| 最大自动继续轮数 | **20** | 不含首次回合 |
| 最大墙钟 | **45 分钟** | 从本次 run 开始 |
| 最大 token | **400k**（有 usage 才精确） | 无 usage 时按上下文占用估算 |
| 最大无进展轮数 | **2** | 连续无变化即停 |
| 同工具重复阈值 | **3** | 同参数连续重复 |
| 最大总迭代 | **120** | 防单轮死循环 |
| 审批等待 | 不占预算 | 用户离开时暂停，不自动拒绝 |

> 预算按“单次 run”计算；用户重新发起任务重新计数。高级设置可改，默认不打扰用户。

## 7. 循环与上下文实现

```
agentic-loop 本轮结束（无 tool call）
  → autonomy.shouldContinue(state)  ← todo/plan/progress/budget
  → 是：追加一条**隐藏的继续指令**（role=user, metadata.autoContinue=true）
        “继续执行当前任务。未完成：…；最近失败：…。
         不要向用户提问，除非需要审批/不可逆/关键信息缺失。完成后给总结。”
  → 同一 engine/abortController/runId 继续下一轮
  → 否：按停止矩阵结束
```

要点：

- **同一个 run**：不新建会话/不新建 runId/不重新计租约；
- 继续指令写入权威日志（保证可审计/可压缩），UI 折叠为一条“自动继续（第 N 次）”；
- 压缩照常每轮前执行；继续指令属于普通 user 消息，不破坏 tool_call/tool_result 配对；
- 事件流新增 `autonomy.round` / `autonomy.stop`，手机/桌面状态条共用；
- 不新增持久目标文件；应用退出即停。

## 8. 审批与不可逆动作

- 审批始终由用户做；**批准动作本身就是继续信号**，批准后不需要再点“继续”；
- 手机远程审批同样：批准→自动恢复；拒绝→run 以 `need_user/denied` 结束；
- 删除、发布、支付、外发、权限提升等不可逆动作单独标记，即使自主模式也必须确认；
- 审批等待不消耗自动轮数/墙钟（或单独计时），用户离开不会导致任务被自动拒绝。

## 9. 进展检测（防“假忙”）

每轮记录一个轻量状态指纹：

```
hash(todo 状态 + 变更文件列表 + 最近验证结果 + 最近工具错误)
```

- 指纹变化 = 进展；
- 连续 2 轮不变 = `no_progress`；
- 同一工具+参数连续 3 次 = `loop`；
- 模型连续说“完成了”但 todo 仍 pending = 一次提醒，再不变则停（不无限催）。

## 10. UX

- **不再显示“继续”按钮**作为默认路径；
- 运行中状态条：`自动推进 3/20`；可点“停止自动推进”（立即 abort）；
- 结束卡片：完成/需要你/预算/无进展，附“为什么停”和“继续一次”“调高预算”“关闭自主”；
- 设置：一个总开关 **自主执行（默认开）** + 高级预算；不要求每个任务选择；
- 用户中途发消息 = 干预：作为 guidance 注入，当前 run 继续；不另起任务；
- 完成/阻塞时系统通知（最小化也有）。

## 11. 与“一键继续”的关系

- 保留“继续一次”作为失败/预算后的手动恢复；
- 删除“每轮结束都问用户”的默认行为；
- 现有 `ContinueBar` 改为自主运行状态条；未开启自主时才回退为一键继续。

## 13. 判据（先写红）

- `AUTO-1` 无 pending todo 的正常问答**不**自动继续；
- `AUTO-2` pending todo + 无 tool call → 自动一轮，且同一 runId；
- `AUTO-3` 完成 todo 后停止，不无限续；
- `AUTO-4` 预算（轮/时间/token）到达即停，原因正确；
- `AUTO-5` 连续无进展两轮即停；
- `AUTO-6` 同工具同参数三次即停；
- `AUTO-7` 审批暂停；批准后自动继续，拒绝则结束；
- `AUTO-8` 澄清/缺信息不自动回答；
- `AUTO-9` 用户取消立即中止，不再追加；
- `AUTO-10` 压缩后继续消息与 tool 配对不被切坏；
- `AUTO-11` 权威日志含每次自动继续（可审计），UI 折叠；
- `AUTO-12` 应用重启不自动恢复（无持久目标）。

变异自证：删触发条件、预算判断、无进展检测、审批暂停，各自变红。

## 14. 分阶段

1. **P0**：ADR + 规则修订 + 设置开关（默认开）+ 预算；
2. **P1**：`autonomy.ts` + 循环接线 + AUTO-1..6；
3. **P2**：审批暂停/恢复、UI 状态条、AUTO-7..9；
4. **P3**：压缩/日志/通知、AUTO-10..12；
5. **P4**：真机长任务调参（默认 20 轮/45 分钟是否合适）。

## 15. 风险与对策

| 风险 | 对策 |
|---|---|
| 烧 token/费用 | 轮/时间/token 三重预算；默认 20/45min/400k；结束卡显示消耗 |
| 连续错步/破坏文件 | 不可逆动作必须审批；无进展/重复调用熔断；run 级快照/回滚已有 |
| 模型“假完成” | todo/验证信号 + 一次提醒 + 无进展停止 |
| 用户失去控制 | 随时停止；中途消息干预；审批仍是硬门 |
| 审计困难 | 每次自动继续写权威日志并标 `autoContinue`；结束原因落库 |
| 与 goal mode 混淆 | 不持久、不跨重启、run 内结束；文档/ADR 明确 |

## 16. 需要改的项目规则

`AGENTS.md` §5.9 现写“禁止目标模式/自动续跑”。本方案需要改成：

> 禁止**持久目标/goal mode**；允许 **run-scoped 自主执行**（默认开启、硬预算、审批不自动、应用退出即停、每次继续可审计）。

这是产品决策变更，需要落到 ADR 与规则文件；实现前先改规则，避免判据与规则冲突。

## 17. 开放问题

1. 默认 20 轮/45 分钟/400k 是否合适（按真实任务调参）；
2. 纯问答是否也默认自主（建议否：无 pending todo 不触发）；
3. 远程手机端是否与桌面共用自主预算（建议共用同一 run 预算）；
4. 是否允许跨应用重启恢复（建议 v1 不允许，保持非 goal mode）。
