# ADR-0006：长程里程碑目标模式（Long-horizon Goal Mode）

- 状态：**接受**
- 日期：2026-11-03
- 取代：`AGENTS.md` §5.9 与 `docs/project-guide/00-AGENT-HANDBOOK.md` §0.5/§3.3 里「禁止一切目标模式」的旧结论；
  也取代 `AUTONOMY-PLAN.md` 的「只做 run-scoped、不做目标」的结论（run-scoped 自主仍保留，作为本模式的**阶段内**子集）
- 相关：`GOAL-MODE-PLAN.md`（设计依据）、`TASK-GOAL-MODE.md`（任务委派）

## 1. 问题：用户反对的不是「有目标」

用户 2026-10-15 的原话是「不要用目标模式迭代，这个开发模式很烂」。把它读成「永远不许有目标」是**误读**：
反对的是 DSH 那套结构 ——

```
长目标 → 模型每轮临时定一个「下一步小目标」 → 做一小步 → 再定下一个
       → 下一个可能推翻上一个 → 粒度不可控（「读文件 / 跑一次测试」也算一步）
```

根因是结构性的，不是措辞：

| 根因 | 后果 |
|---|---|
| 目标**每轮临时生成**，不是持久契约 | 目标漂移、前后不一致 |
| 规划与执行同循环，边做边规划 | 局部最优、短视 |
| 没有全局里程碑 | 不知道走到整体哪一步 |
| 没有验收/证据 | 「做完了」靠模型自述 |
| 重规划无约束 | 新想法一来就推翻旧步骤 |
| 完成定义是「本轮没有 tool call」 | 一步就停或无限微步 |

## 2. 决策

**允许**「长程里程碑目标模式」，并把它做成产品默认（多阶段任务自动进入）：

1. **目标是一次契约**（`GoalContract`）：statement / principles / nonGoals / acceptance / constraints，
   创建后不可变；只有用户显式改意图（或证据证明不可满足、且经用户确认）才变。
2. **计划是一次深规划**（`GoalPlan`）：规划阶段**只读**，一次性产出 3–12 个里程碑 phase，
   按**结果**拆（outcome + acceptance + dependsOn + risks），不是按动作拆。
3. **执行按阶段验收**：Goal Runner 只做调度，每个阶段复用现有 `executeSessionTurn`；
   阶段门禁执行**确定性验收**，模型说「完成」不算。
4. **重规划是事件**：只允许白名单触发（证据推翻假设 / 验收不可达 / 违反不变式 / 阶段连续失败 /
   用户改目标），版本化、记录原因与证据、**已完成阶段不可删除**（缺陷用 rework 阶段补）。
5. **预算默认 unlimited**：不因 token / 时间 / 轮数停止；可选 `capped`，达限**暂停**而非失败。
6. **持久化单 active goal / 会话**：重启后按设置恢复，已完成阶段不重跑；不恢复正在跑的工具进程。
7. **打断只允许四类**：审批/不可逆、真正缺信息、目标 blocked、用户停止/改目标。
8. **没有默认「继续」按钮**：审批通过后自动继续当前阶段。

## 3. 边界：什么仍然禁止

以下都属于「短步 / 无约束目标」，**仍然禁止**（写进 `AGENTS.md` §5.9）：

- 每轮临时生成/推翻目标的「goal mode」；
- 把「读文件 / 跑一次测试 / 看一下」当成一个目标的微步；
- 无证据的重规划（「想到更好的点子」不算触发条件）；
- 用目标模式替代向用户提问（产品取舍、发版这类岔路必须直接问）；
- 用 DSH 的 goal mode / 自动续跑**开发本仓库**（这条不变：开发本仓库仍用 `todo_write` 在单轮内推进）。

## 4. 硬约束（实现层，违反即缺陷）

1. **不新建第二套 Agent 循环**：Goal Runner 只调度，阶段执行走 `executeSessionTurn`。
2. **不自动批准**：审批仍由用户决定；批准后自动继续。
3. **不无证据重规划**；已完成阶段不可删除/改写。
4. **不把预算当默认停止条件**。
5. **目标上下文不能只靠对话历史**：每轮固定注入契约/计划/当前阶段/验收/证据摘要，
   走「尾部易变上下文」通道（不碰 system 前缀），压缩不丢。
6. **单会话单 active goal**；不建跨会话全局目标。

## 5. 与旧资产的关系

- `src/core/goal/goal.ts`（旧 `goals` 表 + `create_goal/update_goal/list_goals` 工具）保留为**历史目标记录**，
  但其「每轮临时建目标」的语义**不再作为长任务的执行机制**；长任务一律走本 ADR 的契约+计划。
- `AUTONOMY-PLAN.md` 的 run-scoped 自主保留为**阶段内**行为（阶段内可多轮、可重试、可换实现路径）。
- 新的目标/计划/阶段/证据/决策使用**独立表**（`goal_contracts` / `goal_plans` / `goal_phases` /
  `goal_evidence` / `goal_decisions`），不与旧 `goals` 表混用（形状与语义都不同）。

## 6. 后果

**收益**

- 长任务有稳定契约与里程碑，用户不必逐轮点「继续」；
- 阶段完成有客观证据，模型自述无法冒充完成；
- 重规划可审计（版本 + 触发 + 证据 + diff）；
- 重启可恢复，长任务不因一次崩溃前功尽弃。

**代价 / 风险**

| 风险 | 处置 |
|---|---|
| 深规划本身错了 | 计划展示 + 契约可改 + 阶段门禁暴露偏差 + 有证据重规划 |
| 阶段粒度失准（太大/太小） | 校验强制 3–12 + 结果导向；G5 真机调参 |
| 无预算烧钱 | 默认不限但显示用量；可设 cap；无进展/连续失败停止 |
| 重启恢复重复副作用 | 阶段标记 interrupted + 证据/工作区检查；不重跑已完成；不恢复工具进程 |
| 模型绕过验收 | 验收由 Runner 执行（命令/产物/文件），模型自述不算 |

## 7. 验收判据

`GOAL-1..GOAL-15`（见 `GOAL-MODE-PLAN.md` §13 与 `src/test/goal-*.test.ts`）。
变异自证至少覆盖：删计划校验、把阶段门禁改成模型自述、允许无证据重规划、去掉目标上下文注入。

## 8. 不在本 ADR 范围（G6，后续）

- Android 本机 Host / 远程网关的 goal 模式移植；
- 跨会话全局目标、跨项目目标编排；
- 目标模板市场、目标分享。

> 桌面端闭环 **不等于** 全平台完成：G6 未做之前，任何「全平台目标模式已完成」的说法都是假事实。
